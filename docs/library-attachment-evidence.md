# Research Library attachment evidence

In **Research library → Attachment evidence**, search across permitted workspace studies and ask temporary, cited questions about explicitly included attachment evidence. Study selection, exact participant-attribute filters, file types and evidence types can be combined. English, Spanish and French controls and answer languages are available.

Verified PDF excerpts (including accepted, researcher-verified OCR), prepared DOCX paragraphs and PPTX slide-text selections retain their exact location and verification version. Included image review notes and PDF/DOCX/PPTX researcher notes and corrections retain their review version and grounding judgment. Image corrections follow the existing image evidence contract and are not projected here. These source types remain distinct from participant quotations and independently established facts. Attachment bytes, visual layouts, charts, unselected paragraphs/slides and speaker notes are not searched.

Only completed, included, non-preview responses in the current workspace qualify. Text verification and observation inclusion are separate opt-ins. A file can have an included excerpt and a private observation, or the reverse. Current source/probe/snapshot checks reuse the existing attachment collectors. The UI labels source type, study, revision, optional concept, review version/reviewer/time, and either the selected page/paragraph/slide character offsets or observation field/grounding. Opening evidence checks current eligibility again; **Open response** opens the authorized full response, including its existing private attachment viewers.

## Retrieval and Q&A

Retrieval uses case-insensitive keywords over included text and study titles, with OR matching and the existing library stop words. This describes default keyword mode; optional [meaning-based retrieval](library-semantic-retrieval.md) searches an explicitly built private index. Search returns at most 50 records, reports the matching count and never counts records as participants, themes or prevalence. Empty keyword terms return the current filtered corpus. Study selection supports up to 100 studies, 2,000 eligible responses and 5,000 included evidence records (five million serialized characters); narrow filters when a request exceeds these bounds.

Q&A first applies the same study/attribute/type filters and search keywords, then ranks matches using question keywords. It supplies at most 30 complete records and 40,000 text characters. Individual records longer than 2,000 characters are omitted from Q&A rather than shortened; searchable records remain intact. No matching records returns a localized insufficient-evidence response without contacting the provider.

The AI payload contains the question/output language and only selected text, opaque evidence ID, study/revision/optional concept, file/evidence type, verification/review version, locator/OCR marker, or observation field/grounding. It excludes full files, unselected text, participant answers, original interview questions, participant attributes, study titles, reviewer names/times, attachment/response/turn IDs, source digests and private review history. The ordinary internal source views retain these authorized provenance fields; the AI payload is a separate whitelist. Selected text and the user’s question can themselves contain personal details; the whitelist does not redact their contents. Review them before sending. Evidence and user questions are untrusted inputs. The provider receives `store: false`, a 2,000-token output budget and a 50-second signal through the shared transport.

A citation must reproduce a complete exact selected record with its exact server-issued evidence ID. Partial, merged, wrong-field and unknown-source citations fail validation. An uncited answer becomes the localized insufficient-evidence message. The server enriches validated citations with current source metadata, adds model/prompt/time provenance, and re-reads the filtered corpus after generation. Any change to included evidence or visible source context rejects the result with HTTP 409. Exact matching establishes source correspondence, not sound interpretation, complete retrieval or resistance to every prompt injection. Review each answer and its sources.

## Access and lifecycle

Internal workspace sessions authorize search and source access, including viewers. Q&A additionally requires edit access and the hosted AI key; it is limited to ten requests per workspace per minute. Participant tokens and other workspace study IDs do not grant access. These routes do not expand external API or MCP scopes. Responses use `Cache-Control: no-store`.

Ordinary Q&A creates no separate index, saved answer, chat or file copy. Explicit **Ask & save draft** is now available through the [saved-answer workflow](library-saved-answers.md), with its own review/export and source-erasure rules. Withdrawal, source changes, exclusion, preview status, incomplete responses, deletion and existing request-driven retention remove evidence from subsequent retrieval. Old opaque evidence IDs become unavailable after a relevant review/source change. Filters, clear, refresh and navigation clear displayed state; aborted or late browser requests cannot restore a previous filter's answer. Current-source failures clear the displayed results/answer. Material already viewed or copied cannot be recalled from another browser.

No schema migration, new provider, domain or environment variable is required. Existing Turso/private Blob/OpenAI configuration applies. Email delivery and human pilot review remain deferred.

## Validation

`tests/library-attachments.test.ts` covers strict filters, whole-record retrieval limits, exact identity/quote validation, localized insufficiency, payload minimization and bounded provider calls. `tests/library-attachments-http.test.ts` exercises actual image/PDF/DOCX/PPTX uploads, explicit inclusion, cross-study/type/attribute filters, provenance, workspace/participant/viewer access, empty/provider-unavailable Q&A, separate correction identities, changed probe context, source edits, withdrawal, exclusion, deletion, incomplete responses and a withdrawal during generation that rejects the completed answer. `tests/library-attachments-browser.ts` covers mobile EN/ES/FR search, drill-down, marked fixture Q&A, filter clearing, late reply isolation and stale-source removal. Browser AI output is a marked fixture, not a real-provider evaluation. The shared test harness now removes its own development build cache after its server stops and preserves the shared production build, bounding disk use during large suites. Hosted evaluation uses an isolated synthetic workspace and real private PPTX/DOCX uploads plus one real provider Q&A operation, then removes its own data and confirms existing users and the paused pilot are unchanged.
