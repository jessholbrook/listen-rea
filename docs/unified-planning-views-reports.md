# Unified planning views and reports

Open **Research library → Research planning**. **Saved combined planning views** stores a named combined scope. **Operations report → Saved reporting views** stores reusable combined report settings. English, Spanish and French controls support mobile.

Settings include work type (all/tasks/reviews), person, collection, title search, month/day/window, finished-work inclusion, language and report time zone. Fixed months/days stay fixed; relative priority queues resolve using current dates. “Assigned to me” resolves for the current viewer. Unassigned scopes match tasks; packets without requested reviewers contribute no review-request row. Priority queues accept unfinished work only; month/day views can include completed tasks and approved current-content reviews. Strict settings reject inconsistent dates or finished-work inclusion in priority queues.

Save a name and choose private or workspace-shared visibility. Private settings belong to their creator and stay hidden from other members, including admins. Shared settings are visible to the workspace and follow existing creator/admin management and creator-only visibility rules. Readers can save private settings and copies without shared-edit or scheduling authority. Combined settings share the existing limits of 25 private views per member and 50 shared views per workspace across all kinds.

Apply or open saved settings from Research planning, the Operations home chooser or a personal/team pin. Opening checks the current saved view version and visibility before restoring exact filters, language and report time zone and loading current results. Personal pins accept accessible private/shared views; team pins accept shared views and require an editor to manage. Settings store no selected tasks, scheduling drafts, report rows, preview signatures or acknowledgement. Pinning does not change visibility or approve a report. Stale views require refresh; unavailable collection/person IDs retain their exact empty scopes instead of widening the queue.

To export, choose the report time zone, generate a fresh preview, review its scope and acknowledge it before downloading CSV or text. The preview shows the reference date and time zone. Relative queues use that report date; on-screen planning priorities use the viewer’s local date. Reports include all matching rows beyond agenda pagination, up to 1,000 rows and 2 MB. Oversized reports fail and require narrower filters rather than truncate.

Every requested reviewer has a separate row, even when several requests belong to one packet. Rows include work type, due date/undated label, collection/title, current person, task/review status, packet status where applicable, overdue status, item version, review coordination version, collection ID, task/packet ID and person ID. Task and reviewer coordinates distinguish duplicate names or titles. CSV neutralizes spreadsheet formulas in user-authored labels; text exports flatten control separators. Source research, private review comments and member email addresses are not copied into files. Downloads are copies that cannot be recalled after later research erasure.

The original stateless report service regenerates current rows and checks a fingerprint containing the actor/workspace/role, full settings, reference date/scope and current row values/versions. Review coordination versions participate, so changing a deadline and restoring its original date still rejects an older export preview. Task edits, current names/availability, decisions, source erasure, applicable role changes and date rollover also require a fresh preview when they change the fingerprint. Preview/download reads preserve valid task, review and history records and do not grant scheduling or research approval.

Saved-setting drafts and prepared reports lock conflicting language, refresh, calendar and scheduling controls. Task/review scheduling hides report controls and keeps its original reviewed workflow. Applying settings refreshes current data without restoring an earlier preview or approval. Failed saved-view loads clear the catalog; failed downloads clear the preview and acknowledgement for explicit recovery. Mutations and downloads are never automatically retried.

Combined settings use strict `unified` and `report_unified` configurations in the existing saved-view store. Combined exports use the existing report preview/export endpoints and source-aware unified projection. Source erasure removes linked task/request rows and revokes populated report snapshots while accessible settings and pins retain exact empty scopes. A fresh empty export cannot recreate deleted research. No new migration, provider call, environment variable, email/domain setup or external calendar synchronization is required.

Validation covers strict schemas, exact settings persistence, private/shared/reader/version rules, pins and sessions, separate request identities, current EN/ES/FR exports, review-version restoration conflicts, task/role/actor/config changes, stable read snapshots, foreign boundaries, exact erased scopes and report caps. Mobile checks cover restored filters/language/time zone, guarded drafts and previews, real reviewed downloads, pinned navigation, fresh report presets, stale-view recovery, restored-date rejection and reader copies/reports.
