# DOCX review-to-report workflow

Researchers can review a submitted DOCX from its response transcript. Select document quality, judge an actually asked DOCX follow-up as supported, unsupported or uncertain, and add notes or a suggested correction. The original question and its prepared-paragraph quote remain visible. Reviews never rewrite participant answers or AI questions. Files with no asked DOCX question accept quality/notes with grounding marked not applicable; they cannot receive question corrections.

Each save appends an attributed, timestamped revision. The quality-review source fingerprint stays compatible with earlier reviews; new grounding judgments also bind the exact probe and the SHA-256 of the current private prepared snapshot. Asked probes must still reference an exact quote in the recorded paragraph of that snapshot. Stale source/probe/version edits fail with a reload message. Earlier quality-only history remains readable and is not treated as a grounding judgment. The existing 50-revision limit remains. Read-only users cannot save; participant, external API and MCP projections omit researcher reviews and corrections.

## Explicit report inclusion

The inclusion checkbox is off by default. Inclusion requires a usable DOCX, a current grounding judgment and a note or correction of at least three characters. Only the latest included revision is projected into a separate **Researcher DOCX observations** appendix, attributed to the reviewer with its revision/time, grounding and original question/paragraph context. Private history, original files and other internal notes are excluded. The projection appears in the analysis view, memo exports/shares, report editions/shares and editable presentation deck. English, Spanish and French report labels preserve the original researcher wording. Authorized researchers can open the private prepared text with the question quote highlighted and return to the source response.

These annotations remain distinct from participant quotations, verified DOCX passages and AI synthesis. They cannot be used as participant citations or change theme/sample counts. Only completed, eligible responses in the current revision/concept scope qualify. Analysis and report projections are assembled by the server, and sharing/export revalidates their exact current sources; client-supplied projections cannot replace them. The initial bounds are 100 observations and 150,000 serialized characters per analysis.

Saving included annotations, changing an already included revision or withdrawing it invalidates analyses, report editions, snapshots and share links. Editing a wholly private review preserves existing reports. Source deletion and response purge remove review history and revoke derived reports while preserving unrelated written answers. Downloaded copies cannot be recalled.

## Validation and next milestone

HTTP checks cover legacy history, immutable original probes, optimistic conflicts, role/workspace boundaries, strict payloads, source/probe binding, default-off/latest-only inclusion, attribution, forgery, report/deck export, private edits, withdrawal, scope/eligibility and erasure. Snapshot checks reject changed prepared bytes, mismatched paragraph/quote and missing provenance. Mobile browser checks cover review/reload, correction/inclusion, separately attributed analysis/report appendices, private source highlighting, source navigation and withdrawal.
