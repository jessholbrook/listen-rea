# Imported recording revisions

Research Library → View source → **Edit imported recording** supports corrections to imported transcript text, speaker labels and timing without replacing the private recording. It supports both staged/transcribed recordings and older manually paired transcript/audio/video imports. A source needs one original recording. Native interviews and transcript-only imports are ineligible.

## Private drafting and review

Editing roles can open the revision editor. Viewers can inspect the current source but cannot read revision drafts or older private history. The editor uses the recording's language: English, Spanish or French. It provides the complete current/draft text, the existing section editor, private playback, a required correction reason and a review attestation. Text changes clear section mapping; label/timing/reason changes clear the review checkbox.

Saving creates an immutable private review entry. It does not alter source turns, search, embeddings, saved answers, briefs, analyses or shares. The first save also freezes the initial reviewed import as the baseline. Older manual imports retain their recorded importer name/time without inventing a reviewer ID or machine-transcription provenance. Partial speaker labels/times can be saved unreviewed. Reviewed saves validate exact full-text coverage, Unicode boundaries, label presence and ordered/nonoverlapping ranges inside the original recording, using the same [speaker review rules](speaker-transcript-review.md).

A separate **Publish reviewed source revision** action requires the latest saved, attested review against the current source. Unsaved changes, unreviewed drafts, already published reviews and stale source/document versions cannot be published. Restoring any history entry copies it into a new unreviewed draft with a new audit entry. It requires fresh review/save/publication; restore never changes the live source directly.

## Publication and dependent research

Publication atomically replaces the source's turns with the exact corrected text and optional reviewed sections. New turn IDs prevent old citations from silently pointing at different words. The response ID, original recording ID/bytes, study, language and frozen interview guide remain. Existing machine model/time/original-transcript and recording hashes remain unchanged; current text-review provenance is updated when present. All imports receive current publication provenance with review/source version, reason, time and publishing actor. No machine provenance is invented for a manual import.

The same transaction clears response-dependent saved answers, semantic vectors and research briefs, including private histories/commentary. It clears study analyses, report editions/snapshots, clips/reels/render jobs and shares, marks study data changed, and removes the response's translations, visual reviews and Pulse coding. Rendered outputs are queued for physical cleanup. Recording source bytes are retained. Source-wide changes deliberately invalidate more than the words edited: regenerate/review dependent research from the corrected source. In-flight Q&A against the former corpus fails its final source check and cannot save a late answer.

Only current published text/section context is returned in normal source/search/Q&A/export paths. Revision history is available only through the editor's authenticated editing-role endpoint. After publication the source dialog closes, old search/answer results clear, and the library refreshes. Reopening retrieves the corrected source and its current publication version.

## Recovery, limits and erasure

Draft saves, restores and publications use immutable request IDs and input hashes. Exact retries return current revision state without creating another review or publishing again. Reusing an ID with different inputs fails. Replaying an older successful publication after a newer publication reports its original published source version and the actual current version, without rollback. The server revalidates current source access before any replay lookup.

Each source supports 20 history entries including the baseline, 150,000 transcript characters, 200 optional sections, 80-character speaker labels, and 3 MiB of serialized UTF-8 revision history. Individual JSON requests retain the application's 250,000-character bound. History follows source retention; it is not an independent copy with a longer lifetime. Source exclusion hides the revision editor; re-inclusion requires refreshing against the current source. Source changes while a review is pending require a new saved review against the latest source version before publication.

Whole-response deletion/retention physically removes the revision document with every baseline, draft, reason, reviewer, publication and earlier text/section map, alongside the source bytes, receipt and dependent research. Late/replayed revision operations cannot recreate an erased response. Copied exports cannot be recalled.

## API

- `GET /api/library/sources/:id/revisions`: editing roles only; current source version, original media metadata, current source text/sections, and private history (or null before the first save). Internal request IDs/input hashes and workspace IDs are omitted.
- `PUT /api/library/sources/:id/revisions`: strict `{requestId,version,sourceVersion,text,sections?,reason,reviewed}`. Document `version` is zero for the first save; source version must match the current response. Saves one private review entry.
- `POST /api/library/sources/:id/revisions/restore`: strict `{requestId,version,sourceVersion,reviewVersion,reason}`. Copies a history entry as a fresh unreviewed draft.
- `POST /api/library/sources/:id/revisions/publish`: strict `{requestId,version,sourceVersion,reviewVersion,reviewed:true}`. Publishes the latest saved attested review once and invalidates dependent research atomically.
