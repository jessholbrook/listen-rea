# Saved reporting views

Open **Research library → Action center → Follow-up workload** or **Follow-up activity history**. Inside **Operations report**, use **Saved reporting views** to save, apply, copy, update or delete a private or workspace-shared configuration. Workload and activity reports have separate lists. Both also appear in **Operations home → Saved workspace views**, where opening a report view restores its original screen and report language. English, Spanish and French controls are available on mobile.

A workload report view stores collection, title query, assignee visibility, report language and report time zone. An activity report view stores collection, exact task, person, action, changed field, local date bounds, report language and report time zone. Use the existing screen language control to choose a report language, and the report time-zone field to choose a valid time zone. These settings are saved exactly across sessions. Activity date filters use the selected time zone; workload dashboard counts still use the viewer’s local calendar, while the report preview explicitly computes its reference date in the report’s chosen time zone.

Applying a view checks its current saved version and visibility, restores the configuration, resets pagination and reloads current task data. It does **not** generate a report or restore old rows, a fingerprint, acknowledgement or file. Generate and review a fresh preview before downloading. Original report limits, source validation, member/workspace/role fingerprint checks and stale-download rejection still apply. Missing source/task/collection IDs remain exact unavailable filters rather than widening the scope or restoring deleted research.

Private views are visible and manageable only by their creator, including readers; workspace admins cannot see other members’ private report settings. Editors can create shared views. Everyone in the workspace can apply shared views and save private copies. Current shared creators with edit access and admins can update/delete shared views, but only the creator can change visibility. Departed creators’ private views are pruned; their shared views remain with an unavailable creator label. Names and free-text queries may contain sensitive information, so choose shared visibility deliberately.

Updates explicitly capture the current screen’s report settings and replace the preset’s name, visibility and configuration. Application, updates and deletion use versions; stale or unavailable cached views clear their catalog and require explicit refresh. Writes are not automatically retried. An open saved-view form/request guards report generation, time-zone editing, filters and navigation. An open report preview/request disables saved-view actions. Closing the relevant form or preview releases those controls.

This extends the existing saved-view store and permissions without a new endpoint, provider, migration or environment variable. Existing quotas of 25 private views per person and 50 shared views per workspace apply across review, follow-up and report kinds together. Records contain settings and names only—no report rows, generation date, preview signature, review acknowledgement, downloaded bytes, source text or research approval. The existing report endpoints continue to generate files only from current data; previously downloaded copies cannot be recalled through source erasure.
