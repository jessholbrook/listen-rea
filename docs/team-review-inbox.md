# Team review inbox

Open **Research library → Review inbox** for handoff review requests across workspace collections. The default view shows requests awaiting your own current-content decision. English, Spanish and French controls are available. The inbox uses original packets and review records, without saved queue copies, email, domains or provider calls.

## Workflow

Filter by collection, reviewer, reviewer decision, packet status and packet/collection title. Filters intersect. Reviewer choices include your requests, everyone, a particular member and packets with no requested reviewers. Choose **All decisions** to see unassigned packets. A person's approval and a packet's overall readiness are separate: you can have approved a packet that still awaits another reviewer. Reset restores your pending requests across collections.

Each row shows current packet/collection titles, requested reviewers and decisions, open-comment and remaining-review counts, packet status and packet update time. It excludes the packet summary, findings, sources and private comment bodies. All saved packets can appear when the filters permit them, including summary-only or unassigned packets.

Statuses are **Blocked** when comments remain open, a requested reviewer is unavailable or selected contents are ineligible; **Awaiting reviewers** when more current-content decisions are needed; **Ready for final approval** when review is complete but export has not been approved; and **Approved for export** after the separate current final approval. Readiness never itself approves export or underlying research. Rows sort by the earliest matching pending [review deadline](review-planning-deadlines.md), dated requests first, then blocked/awaiting/ready/approved priority, newest packet update time and packet ID. Rendering is limited to 20 rows per page. Counts describe all matching packets.

**Open handoff packet** opens the existing handoff editor directly. Resolve comments, submit your own reviewer decision or perform the separate final approval there. **Close packet and refresh inbox** reloads the queue after your work. A stale row cannot silently open a replacement packet with a different generation ID. The collection dashboard is also available for source context and existing answer/brief reviews. Closing it refreshes the inbox. Source correction/erasure in the parent source viewer refreshes the inbox through the existing source-change signal. Other sessions' changes require explicit refresh and remain protected by the original packet/review conflict checks.

Save editor changes before closing, refreshing, changing language or navigating away: these actions reload saved state and discard unsaved text. A disappeared collection/reviewer filter retains an explicit unavailable option after refresh, so its selection never silently expands to the whole workspace. Interface language changes reset filters to the default personal view.

## Current records and access

`GET /api/library/review-inbox` returns minimal current packet/reviewer metadata, collection IDs/titles, current editable member IDs/names and current user ID/edit capability. It exposes no workspace IDs, member emails, source fingerprints, signatures, request hashes, comment bodies, packet summaries, transcripts or finding text. Public requests return 401; other workspaces see only their own records. Existing workspace readers can view the queue and open a read-only packet; mutations use original editor-only routes. Inbox mutations return 405; unsupported nested routes return 404.

The server validates each existing packet with the same current task, research, dashboard and feedback logic as its editor, inside one transaction. Content/context changes and unavailable reviewers revoke approvals through those existing rules. Source/collection/packet deletion and orphan-feedback cleanup are reflected before rows return. A final existence pass excludes packets erased while validating shared dependencies later in the same request. The existing limit of 50 collections bounds the queue to 50 packets, one per collection; only collections with a saved packet require full packet validation. No inbox documents, copied labels or review snapshots are persisted. Refreshing an inbox can synchronize stale review decisions but never submits an approval or creates a source checkpoint.
