# Researcher PDF observations in analyses and reports

In **Responses → participant → Researcher PDF review**, select **Include PDF notes and corrections in analysis and report appendices** and save. Inclusion is off by default. It requires a usable-PDF judgment, a current grounding assessment and at least three characters in either notes or correction. PDFs without an asked follow-up use grounding “not applicable” and allow notes only. A correction can describe an unsupported question without asserting that the document supports it.

Only the latest explicitly included revision is copied into a new analysis. The separate **Researcher PDF observations** appendix identifies the reviewer, review time/version, PDF, response, turn and original question/page anchor when one was asked. Notes, corrections and quoted document context retain their original wording; English, Spanish and French labels describe their distinct roles. Signed-in researchers can follow a source link and open the private PDF at the cited page. Share links and exported decks contain the included annotation text and source identifiers, not public file access or the private correction history.

These are researcher annotations, not participant quotations or verified PDF passages. They do not add participants, code themes or alter prevalence/sample counts. Verified passage selections remain a separate appendix and can coexist with annotations from the same PDF. Participant-theme analysis, participant-evidence Q&A, interview follow-ups and passage/image synthesis do not receive these annotations. [PDF observation synthesis](pdf-observation-synthesis.md) and [observation Q&A](pdf-observation-qa.md) are separate explicit requests using only included annotations; no automatic synthesis or scoring is added.

Inclusion uses the current workspace/study, eligible completed non-preview non-excluded response, exact file/answer fingerprint, current probe fingerprint, review version and analysis revision/concept scope. Old quality-only reviews remain private until a current structured review explicitly includes them. Draft attachments cannot be reviewed. A stale question requires reload. At most 100 observations totaling 150,000 serialized characters can enter one analysis.

The server derives all appendix metadata. Analysis/report edits cannot replace it with client-provided observations; participant citation checks continue to require exact text from a participant answer. Report creation, sharing and deck export verify snapshots against current included reviews, including reviewer attribution and question context.

Saving inclusion, changing an already included review or withdrawing inclusion invalidates saved analyses, report editions/snapshots and share links for the study and advances its data version. Regenerate the analysis and review the new report before sharing again. Private-only review edits leave existing reports intact. Source/response erasure continues to remove the reviews and private files and invalidate derived output. Previously downloaded or copied text cannot be recalled.

Validation covers default-off inclusion, usable/grounding/content gates, correction-only inclusion, private history isolation, exact question/page snapshots, reviewer attribution, scope/eligibility/stale-source checks, forged metadata and participant-citation denial, separate verified passages, localized labels, text/deck exports and edit/withdrawal/erasure revocation. Mobile Chromium checks saved inclusion after reload, analysis/report appendices, actual cited-page pixels, source navigation and withdrawal. Hosted checks use a temporary synthetic study with a marked asked-question fixture and no AI generation; temporary accounts and private files are removed afterward.

[AI synthesis of included researcher PDF observations](pdf-observation-synthesis.md) is implemented with exact field/review citations and human review before sharing.
