# AI synthesis of included researcher observations

In **Analysis**, create a fresh analysis with included attachment observations, then choose **Synthesize observations with AI**. This is a separate, explicit request; running ordinary participant analysis does not automatically synthesize notes. Existing inclusion, completed-response, preview/exclusion, concept/revision and source-fingerprint gates still apply.

The model receives only the included note text, image IDs, review revisions and requested reporting language. It receives no pixels, participant answers, reviewer identity fields, descriptions or private correction history. Image permission for AI follow-ups is independent of this text-only researcher action. Output is a separate set of tentative findings with exact researcher-note citations and limitations. It does not add participant themes, people, prevalence or quantitative results.

Every citation must match an included image ID, its saved review version and an exact contiguous excerpt from that note. Missing, invented, wrong-version or paraphrased citations reject the output. A finding requires at least one citation; an empty set of findings with limitations is valid. Structural citation validation does not prove an interpretation is sound. The prompt instructs the model to preserve uncertainty/conflicting observations, ignore embedded instructions, avoid identity/sensitive inference and say when notes are insufficient.

Generation is bounded to one text request, a 50-second deadline and 3,000 completion tokens with `store:false`. Up to six findings, ten citations per finding and the existing 100-observation/150,000-character analysis limit are supported. Provider failures or invalid outputs do not replace an existing synthesis. Saved provenance records the configured model, prompt version and generation time. Usage is recorded separately as `attachment-synthesis`.

Generated synthesis starts **Draft · review required**. Inspect its note citations and source links, edit titles/interpretations/limitations or remove unsupported findings, then check the review attestation and **Save synthesis review**. The authenticated reviewer and server time are recorded. Editing form text clears the local attestation. Saving or regenerating synthesis clears the overall memo review, report editions/snapshots and share links. Review the memo again, create/review a new report and share afterward. **Discard observation synthesis** removes only the interpretation and derived reports; included source notes remain.

Unreviewed synthesis blocks marking the analysis reviewed, sharing it or creating a report edition that could include it. Reviewed synthesis appears separately in memo text/downloads, shared report text and PowerPoint, with citations labelled as researcher notes. Typed report provenance cannot be replaced through report block edits. External REST/MCP analysis projections and participant payloads remain unchanged. Cited study Q&A continues to use participant themes; observation Q&A is not added by this stage.

Generation and review use the analysis ID/version plus source data version. If notes, inclusion, eligibility, report language or analysis change during generation, the late result cannot overwrite the new state. All citations and live source records are checked again at commit and export. Source-note changes/withdrawal, image erasure, whole-response deletion and retention remove dependent synthesis/report data through the existing cleanup paths. Downloaded copies cannot be recalled.

Local tests cover exact-source citation validation, minimized payload, bounded non-stored requests, server provenance/draft state, provider failure, draft publication denial, review attribution, optimistic conflicts, private projections, report metadata protection, text/PowerPoint export, discard and withdrawal. HTTP checks run against development and compiled production servers. Mobile Chromium uses an explicitly seeded draft to verify editing/review, source links, discard and layout without a model call. Seeded fixtures do not claim live generation.

Hosted evaluation uses disposable synthetic notes with the existing hosted key: useful English and Spanish observations, conflicting French observations and an instruction-only injection that should yield no findings. These are bounded regression cases used during implementation, not held-out evidence or a real-study accuracy estimate. Hosted lifecycle checks verify draft gating, authenticated review, sharing/export, source invalidation and complete cleanup. Deployment notes record the final result.
