# Saved follow-up views

Open **Research library → Action center → Saved follow-up views**. The task queue and follow-up activity history each have their own saved-view list. Both are also available from **Operations home → Saved workspace views**. Controls are available in English, Spanish and French, including on mobile.

Set the screen’s filters, choose **Save current view**, give it a name and choose private or workspace-shared visibility. Applying a saved view checks its current version and visibility, reloads the original workspace projections and resets pagination. Views persist in the hosted database across sessions. A changed or unavailable preset clears the local catalog and requires an explicit refresh before trying again; writes are never automatically retried.

Queue presets retain collection, assignee, status, due-date range and search text. “Assigned to me” resolves to the person applying the view; relative due dates follow that viewer’s current local calendar. History presets retain collection, exact task, person involved, action, changed field and inclusive calendar dates. Dates default to the viewer’s browser time zone; reporting controls can explicitly override it for activity filters and files. A preset does not save pagination, language, time zone, selected triage tasks, editing drafts, permissions, research results, source links or recording bytes. Its user-authored name and search text may contain sensitive information: choose shared visibility deliberately.

Private presets are visible and manageable only by their creator, including when that creator is a reader. Workspace admins cannot see another person’s private filters. Editors can create shared presets; all current workspace members can apply shared presets or save private copies. Shared creators who retain edit access and current admins can update or delete them. Only the creator can change visibility. Former members’ private views are pruned on catalog access; shared views remain, with their creator displayed as unavailable. Foreign-workspace and anonymous access stays blocked.

Updates explicitly replace the preset’s name, visibility and filter values with the current screen’s captured filters. Updates, deletion and application check versions; competing updates cannot silently overwrite one another. An open preset form or request guards filters, mode/language changes, refresh and task controls. Task editing, triage or research drill-down disables preset actions until that workflow finishes.

Filter IDs are coordinates, never access grants. Missing or erased collections, tasks and people remain exact unavailable filter values; applying them cannot widen the scope, restore deleted research or recreate activity. Saving or applying a view does not edit tasks, approval state or history. Current data validation may still perform the original source/assignee cleanup.

This extends the existing saved-view store and routes without a migration, new provider, environment variable or email/domain requirement. The existing limits—25 private views per person and 50 shared views per workspace—apply across review and follow-up kinds together. Existing review presets keep their original schemas and navigation.
