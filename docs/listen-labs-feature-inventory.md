# Listen Labs: public feature inventory

Reviewed October 19, 2026. This is a feature reference for designing our own research product. It documents public descriptions, not a tested reconstruction of Listen's private application or backend.

## Evidence and scope

The strongest sources are the current [support documentation](https://docs.listenlabs.com/llms.txt), followed by specific release notes, then product pages. The original `listenlabs.ai` site also exposes a sitemap pointing to `listenlabs.com`. The marketing site's `/docs` link leads to an older Mintlify API reference; the support site's API v2 documentation is substantially newer.

**Documented** means a public help page or API contract describes the behavior. **Announced** means a release note describes it. **Claimed** means a product page describes it; effectiveness and availability have not been independently tested. None of these labels means we verified the feature in a logged-in account. Downloading a source does not establish product performance.

Phases refer to [the build plan](build-plan.md): P0 decisions, P1 text workflow, P2 voice pilot, P3 analysis, P4 study depth, P5 specialist modules, P6 ecosystem. Phase assignments are our recommendations.

## Conflicts and limits to carry into design

1. **API documentation:** Older Mintlify docs say keys are requested through support and mainly cover response endpoints. Current API v2 describes self-serve keys and create/launch/read/delete operations. Use API v2 for current scope. We did not authenticate or execute those operations.
2. **Language counts:** FAQ says 90+ text languages and 40+ voice; a newer release says 120+ interview/reporting languages. The emotion product page itself mixes 50+ and 100+. Build a tested modality-by-language matrix rather than promise a headline count.
3. **Panel reach:** Recruitment docs say 30M+/45+ countries; homepage says 50M+; quality marketing says 70+ countries. Treat this as partner-dependent supply, not software parity.
4. **Collaborator role:** The FAQ calls collaborators read-only. The specific role guide and February release say they can edit/create but cannot launch. Prefer the specific guide; verify in-product if exact parity matters.
5. **Screen sharing:** FAQ excludes single-tab capture; the dedicated guide includes it. iOS recording is described as live in the guide and a phased rollout in the release. Do not promise universal availability.
6. **Publish versus recruit:** FAQ separates publishing revisions from starting recruitment; API launch publishes and opens the link. Our design should separate revision state from fielding state explicitly.
7. **Response limits:** FAQ allows already-started interviews to finish, so completed counts can exceed the limit. Our admission/cap behavior needs an explicit choice.
8. **Quality timing:** Feature marketing describes live grading; support docs describe post-interview scoring plus participant checks. Exact orchestration, thresholds and model accuracy are unknown.
9. **Imports:** FAQ says full unstructured transcript upload is unsupported; a later release describes batch video import. Those are different formats and should not be merged into a claim of universal importing.
10. **Scientific claims:** Emotional inference, fraud detection, predictive Twins and statistical models need independent evaluation. A model-generated explanation does not establish accuracy.

No private prompts, model weights, internal architecture, commercial partner access, exact algorithm parameters or measured product accuracy were recovered.
