# Meaning-based Research Library retrieval

Research Library supports an explicit **Meaning + keywords** method for transcript search/Q&A and attachment evidence search/Q&A. Keywords remain the default. This milestone includes indexing, retrieval, exact source citations, saved attachment-answer provenance, source withdrawal and index clearing as one workflow.

## Using it

Open Research Library, choose transcript or attachment evidence, then select studies and other filters. **Check coverage** reads current index coverage without calling OpenAI. **Build next batch** explicitly sends eligible source text to OpenAI and stores private derived vectors. Repeat for additional batches when coverage is partial. Choose **Meaning + keywords** to search or ask a question using related wording; search also sends the query/question text to OpenAI. Nothing indexes automatically.

The interface and notices are available in English, Spanish and French. Coverage counts evidence records or transcript chunks, not participants. The semantic method retrieves only the currently indexed portion of the filtered corpus. An empty index returns no evidence and makes no embedding request; it never silently falls back to keywords. Keyword mode works independently of the index. A partial index can miss relevant sources. Nearest-neighbor ranking is not confidence, prevalence, interpretation quality or evidence sufficiency.

## Eligible sources and retrieval

Transcripts come from current completed, included, non-preview responses in the authorized workspace, including reviewed external imports. Transcript text is split into exact contiguous chunks of at most 1,500 UTF-16 characters, with up to 150 characters of overlap; results retain original response/turn IDs and exact start/end offsets. Attachment items come from the existing included verified PDF/DOCX/PPTX passages and explicitly included researcher observations/corrections for supported image/PDF/DOCX/PPTX files. Source type and researcher authorship remain explicit.

`text-embedding-3-small` produces 256-dimensional vectors. Index version is `2026-10-21-library-semantic-v1`. Retrieval combines cosine-neighbor ordering and text-only keyword ordering by reciprocal rank fusion (`hybrid-rrf-v1`, k=60), restricted to current indexed sources. It has no relevance threshold: unrelated nearest neighbors can appear. Search returns at most 50 items; its semantic total describes the indexed candidate pool, not a count of relevant matches. Q&A supplies at most 30 retrieved excerpts, with the existing source-text budget (40,000 attachment characters, 50,000 transcript characters).

Q&A validates exact quotes and source identities and rechecks the source corpus after generation. This checks grounding, not correct interpretation. Saved attachment answers freeze server-derived retrieval method, embedding model/version and coverage with the original answer. Latest approved Markdown/plain-text and CSV exports include retrieval provenance. Existing saved keyword drafts and retries remain compatible.

## Privacy, authorization and deletion

The embedding request contains only eligible text strings and fixed model options. It omits separate study titles, names, attributes, metadata, file bytes and review history. Source text itself may contain identifying information. Embeddings follow the provider's standard data handling; vectors are derived private research data. Vectors are stored in workspace-scoped `libraryEmbedding` documents with source IDs, dependency references, fingerprints, model/version and timestamps, without another copy of the original text. Query vectors are not stored. Usage records contain operation/model/token counts, not query or source text.

Every status/build/search resolves current authorized sources. Source fingerprint mismatches are pruned and cannot participate in retrieval. Existing centralized mutation cleanup physically removes affected vectors when source inclusion, review, verified passages, prepared content, response eligibility/attributes or study title changes, or when files/responses are erased. Request-driven retention uses the same erasure path. Saved answers depend on every generation input, including uncited excerpts, and are erased when their source dependencies change.

Viewers can inspect coverage and search; only editing roles can build or clear. Public/participant callers and other workspaces cannot use the index. Clients cannot submit vectors. **Clear index** clears all vectors of the selected source type throughout the workspace, regardless of the current filters. A content-free generation counter prevents an already running build or search from restoring/using the cleared index. Clearing derived vectors leaves original sources and otherwise valid saved answers intact.

## API and limits

- `POST /api/library/semantic/status`: normal library filters plus `scope: "transcripts" | "attachments"`.
- `POST /api/library/semantic/index`: same body; builds the next missing batch and returns `built` plus coverage.
- `DELETE /api/library/semantic/index`: strictly `{scope}`; clears that source type throughout the workspace.
- Existing transcript and attachment search/Q&A routes accept `retrieval: "keyword" | "semantic"` (default `keyword`). Source drill-down keeps its existing strict contract.

Semantic snapshots support at most 100 studies, 2,000 eligible completed responses and 5,000 evidence items/chunks, with corpus bounds applied before attribute segmentation. Narrow study/type filters when needed. Each explicit build handles at most 100 whole excerpts and 40,000 characters. The workspace stores at most 2,000 vectors across both source types; clear unused source-type indexes to free capacity. Build and query requests are limited to 10 and 30 per workspace per minute respectively. Embedding requests have a 25-second timeout. Queries require 3–4,000 characters. Source changes or index clearing during a provider request reject stale results rather than publishing them.
