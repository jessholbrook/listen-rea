# Research Library collections

Research Library → Collections groups existing included interviews and existing research briefs. Create a title, select members and save. Open an interview or linked brief from its collection, or choose Search this collection. The Search & ask and Attachment evidence tabs also offer a collection selector. The manager is available in English, Spanish and French.

Collections share workspace access. They do not grant access, create public links, copy transcripts/briefs, change source inclusion, or approve findings. Only explicitly selected interviews supply evidence; linking a brief does not include its text or automatically add its underlying sources. Reviewed originals and export approvals keep their existing rules.

## Retrieval and review

- Existing study, response, evidence and provider budgets still apply. Keyword and meaning-based transcript/attachment searches, index coverage/build, cited Q&A and saved drafts intersect the selected collection with the current study, attribute and evidence-type filters. An empty collection yields no evidence. Missing, deleted or foreign collections return 404; they never fall back to the whole workspace.
- Search index records remain source-owned. Collection retrieval/build does not erase unrelated vectors. Explicit clearing of a source-type index still clears that index across the workspace, following the existing index controls. No index build or paid provider call occurs when creating/editing collections.
- Saved answers retain the collection ID in their filters. Changing interview membership removes all saved answers generated with that collection and their dependent briefs, including uncited generation dependencies and commentary. Deleting a collection does the same. Original interviews and other linked briefs remain. Separately, actual source withdrawal/erasure still removes every answer or brief dependent on that interview, including uncited generation inputs, under the existing library lifecycle rules. Collection title edits, reordering the same interviews or changes to linked brief membership do not change the interview evidence set or remove its answers.
- Source withdrawal, incompletion, preview status, study unavailability and source erasure physically prune interview membership, advance the collection version and invalidate its scoped answers/dependent briefs. Restoring an excluded source does not automatically re-add it. Removed/invalidated briefs are pruned from collection references. Collections store only a title and current IDs; there are no retained source copies, descriptions, membership histories or erased member titles.
- An in-flight Q&A/index build rechecks the collection and sources before committing. Concurrent membership changes or deletion prevent stale answers/vectors from being saved. Source-level validation still applies to every linked brief, saved-answer citation and private recording. First-read validation also handles a historical source edit that bypassed normal update hooks: pruning an uncited collection member invalidates the whole scoped answer before returning it.

## API and limits

Authenticated workspace members can read `GET /api/library/collections` and `GET /api/library/collections/:id`. Existing editor roles can create, edit and delete. Creation takes strict JSON `{requestId,title,interviewIds,briefIds}`; editing takes `{version,title,interviewIds,briefIds}`; deletion takes `{version}`. Title length is 3–160 characters. Defaults for member arrays are empty. Each ID must be a distinct UUID; at most 200 interviews and 30 briefs per collection, and 50 collections per workspace. Included interviews and linked briefs must exist in the same workspace. Collection mutations, pruning and invalidation run in transactions.

Creation retries with identical settings reuse the collection; changed settings conflict. Current-state update retries reuse the existing version; divergent stale edits and future versions conflict. Creation replay after deletion is blocked by a workspace-scoped content-free request tombstone. Removed scoped-answer requests also receive content-free tombstones so an old save retry cannot regenerate an invalidated answer. These tombstones expire after 90 days, with cleanup driven by collection requests.

Existing transcript, attachment and semantic filter APIs accept optional `collectionId`. Saved-answer source resolution keeps that scope. No collection title, membership list, linked brief text or private organizer history is added to model payloads; only the matching existing evidence is passed through the established Q&A/index contracts.
