# Verified PDF passages in analysis and reports

In **Responses → participant transcript → PDF text and verified passages**, extract text, select passages and compare their cited PDF pages. Check **Include this verified passage selection in new analysis and report appendices, including shared reports and exports**, then confirm the verification statement and save. Inclusion is off by default, including for verifications created before this stage. A selection must contain at least one exact verified passage to be included. See [extraction and verification](pdf-text.md) for limits and corrections.

Create a new analysis after saving. The **Verified PDF passages** appendix shows excerpts, physical PDF page numbers, the source PDF/response/turn, researcher attribution, verification version and time. The page button opens the cited page through the existing private viewer; the source link opens its transcript. Reporting labels support English, Spanish and French; quotes retain their exact original text. Physical PDF page numbers can differ from page numbers printed on a document.

Analysis snapshots and report editions retain this evidence as separate, server-owned metadata. Client edits cannot replace it. Memo downloads, reviewed memo shares, report shares and presentation exports include the appendix. Presentation speaker notes preserve citation provenance. Shared appendices expose only explicitly included excerpts and attribution, not the raw extraction, correction history, original file bytes or interview tokens. Reading a PDF itself still requires an authorized workspace session or the original participant capability.

These are document excerpts verified by a researcher, not interview quotations. They do not add respondents, theme codes or prevalence, and cannot be substituted for participant-answer citations. Participant-theme AI analysis, Q&A and image-note synthesis do not receive PDF passages, bytes or descriptions. A separate [explicit PDF synthesis request](pdf-synthesis.md) sends only included verified passages and their citation references. Participant responses and external REST/MCP analysis projections do not gain these excerpts. A researcher can still deliberately copy text into an editable narrative; those manual edits remain the researcher's responsibility.

Only complete, included, non-preview interviews in the requested revision and concept scope contribute. Collection checks the current PDF media row, file/prompt/answer fingerprint, immutable extraction digest and exact page/character ranges. Report creation, export, rebase, restore and sharing revalidate saved evidence against the current included verification. Each analysis is bounded to 100 PDF selections and 150,000 serialized characters; each selection retains the existing ten-passage/1,000-character limits.

Saving an included selection, changing it, or withdrawing inclusion removes the study's analyses, report editions/snapshots and share links and advances its response-set version. This also prevents an in-flight analysis from committing against the old version. Create a fresh analysis and report after saving. Individual PDF erasure and erasure of a related image-generated question also remove affected derived reports/shares; whole-response deletion and retention use the existing source cleanup. Previously downloaded exports or already-fetched copies cannot be recalled.

Validation covers opt-in/default behavior, exact metadata and attribution, memo/report shares and PPTX slide text, rejection of forged participant citations, immutable edition metadata, eligible source/scoped collection, stale fingerprints, withdrawal, file and related-image context erasure, and localized labels. Mobile Chromium exercises real text selection, inclusion, cited-page pixels, analysis/report appendices, source navigation and withdrawal.
