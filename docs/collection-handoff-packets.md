# Collection handoff packets

Open **Research library → Collections → Open review dashboard** to create the collection's private handoff packet. The same dashboard is available through the action center. One current packet per collection contains a researcher-authored title/summary, up to 20 approved findings generated in that collection, and up to 50 selected unfinished follow-ups. Summary-only packets are supported. Packet language is independent of interface language; English, Spanish and French labels are available. Finding text stays in its saved answer language, without automatic translation.

## Review and export

Save the draft, complete any [requested internal reviews and comment resolution](internal-handoff-review.md), read the current preview, attest that the summary/findings/sources/follow-ups have been reviewed, then explicitly approve the packet for export. Saving a real content change clears packet approval. Unsaved edits disable approval and downloads. Save drafts before refreshing or changing tasks: refreshing the packet/context reloads saved content and discards unsaved editor text.

Text and CSV downloads include the summary, current approved finding text with exact cited evidence and existing source/provenance links, and selected unfinished task titles, versions, assignments, due dates and source links. Packet and finding/task IDs and versions preserve attribution. Links open current authenticated research; exports create no public share or copied recording. CSV fields use existing formula/quote/newline escaping. Each format is limited to one million characters. A copied download cannot be recalled.

Task completion is not research approval. Completed tasks cannot be selected for an open follow-up packet; if a selected task completes, remove it from the selection and review the revised packet. Draft/unapproved findings cannot be selected or exported. Current previews show eligibility warnings instead of unapproved finding bodies. Checking sources, creating a packet or approving it never approves underlying answers, briefs, transcripts or task progress.

Approval binds to current packet content, collection/source/dashboard state, selected finding revisions and the current collection task records/assignee names. Context changes block export until refreshed and reviewed again. New tasks or changed unselected task records also require re-review because the summary may describe the collection's current work. Task changes made beside the packet refresh it; direct answer-review closure or dashboard refresh also reloads it. Other sessions' changes are checked again on every review/export. Divergent stale writes and approvals return conflicts and clear the displayed packet/editor until refresh.

## Withdrawal and storage

Only the current authored packet is stored, with version/timestamps and dependency IDs; no finding/task text snapshots, assignee name copies, earlier summaries or edit history are retained. Creating, changing or approving a packet captures all current collection interview memberships, linked briefs, scoped saved answers and task IDs. Dependency references accumulate during that packet's lifetime, including deselected items.

Removal/exclusion/erasure of a captured member interview, unlink/deletion of a captured brief, deletion/invalidation of a captured answer, deletion of a captured task, or collection deletion removes the whole packet, including title/summary. This deliberately includes unselected research/tasks captured while composing or reviewing it. Linked briefs retain existing historical answer/source dependencies, protecting summary context from later source erasure outside the collection's interview membership. Source corrections that invalidate captured findings remove the packet; corrections with no lost dependencies retain the draft but block prior approval through the current source signature. Summary text is researcher writing: provenance does not establish interpretation accuracy or completeness, and arbitrary text copied from unrelated, unlinked research cannot be tracked automatically.

Content-free workspace/request digests prevent deleted create requests from recreating summaries. They contain only a SHA-256 ID, workspace ID and timestamp, with no plaintext source/collection/packet IDs or content; they are retained without expiry. A replacement packet receives a new UUID, preventing old generation/version writes from affecting it. Cleanup runs in existing collection/source/task lifecycles and again on packet access. Stale-source cleanup is committed before a write/export can reject, so a failed stale export cannot roll back deletion of withdrawn summaries.

## API and access

- `GET /api/library/collections/:collectionId/handoff`: current packet or null, current eligible-choice metadata, signature and preview. Workspace readers can view and download an approved packet; only existing editor roles can create/change/review/delete it. Foreign/missing collections are unavailable. No request/input hashes, stored dependency arrays, workspace IDs, approval digests or earlier summary revisions are returned.
- `POST` at that route: strict `{requestId,title,summary,language,answerIds,taskIds}`. Titles are trimmed, 3–160 characters; summaries are trimmed, up to 8,000 characters. IDs must be unique and eligible in this collection. Exact creation retries return current state; changed request reuse returns 409. Only one packet can exist per collection.
- `PUT`: strict `{id,version,title,summary,language,answerIds,taskIds}`. Future/divergent stale versions return 409; exact current-content retries reuse current state. Real edits reset approval and increment version.
- `POST .../handoff/review`: strict `{id,version,signature,reviewed}`. `true` explicitly approves current eligible contents; `false` withdraws packet approval. Current-content retries preserve the review timestamp. Approval never changes underlying research.
- `GET .../handoff/export?id=...&version=...&signature=...&format=md|csv`: current generation, version, signature and approval are revalidated transactionally. Stale/unapproved exports return 409; missing/withdrawn packets return 404. Responses are private/no-store attachments.
- `DELETE .../handoff`: strict `{id,version}`; conflicts return 409. Other routes/methods are unavailable.
