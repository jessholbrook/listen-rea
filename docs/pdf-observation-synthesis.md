# AI synthesis of researcher PDF observations

Create an analysis containing [explicitly included researcher PDF annotations](pdf-observations.md), then choose **Synthesize PDF observations with AI** in Analysis. This is a separate researcher action. Including notes in an appendix alone does not send them to AI.

The provider receives only the latest included notes, corrections, question-grounding judgments, PDF IDs, review versions and reporting language. It does not receive PDF bytes, extracted page text, original asked questions/anchors, participant answers, reviewer names, response/turn IDs, source fingerprints or private revision history through this request. Text written inside an included note/correction is transmitted as part of that field. There is no automatic document rereading or OCR.

Generation uses a non-stored structured request (`store:false`), 3,000 output tokens and a 50-second request deadline, with at most six requests per workspace per minute. Existing study/workspace AI budgets apply. These are application request bounds, not a provider retention guarantee. The prompt treats annotations as untrusted data, asks for tentative interpretations, preserves uncertainty and forbids claims of document verification, participant prevalence, identity or sensitive traits. Empty findings with an insufficiency explanation are valid.

Each finding cites an exact PDF ID, current included review version, field (`notes` or `correction`) and contiguous quote from that exact field. Invented sources, versions, quotes and cross-field substitutions are rejected. Citation identity is a mechanical check; a researcher must still assess whether the interpretation is supported.

Generated synthesis is a draft with server model, prompt version and generation time. Review its interpretations, remove unsupported findings, edit wording/limitations and explicitly check the review statement before saving. Review records the authenticated reviewer/time. Editing the form clears its review checkbox. The memo requires its own review after synthesis review. Unreviewed synthesis blocks memo sharing and report creation/sharing/export. Included observations and participant themes remain separate, with no new respondents or prevalence counts.

Reviewed synthesis appears separately in the analysis, memo text download, shared memo/report and editable deck. Field-specific citation labels in English, Spanish and French retain original quote text. Signed-in source links lead to the original PDF review; shared text does not grant access to private files. The read-only external API and MCP projections do not gain these annotations or syntheses.

Successful generation, regeneration, review/edit or discard increments the analysis version, clears memo review and revokes report editions/snapshots and share links. Discard preserves the included annotation appendix. Source edits, withdrawal or erasure continue to invalidate analyses and reports. Requests verify exact sources and analysis/language/data versions before generation and again before saving, preventing late results from restoring changed or erased data. Provider/validation failures preserve the previous saved synthesis. Downloaded copies cannot be recalled.

Validation covers field-specific exact citations, minimal provider payload, generation bounds, non-stored requests, empty findings, invalid/unavailable providers, workspace access, optimistic edits, review gates, immutable provenance, private projections, report/deck output and withdrawal/discard cleanup. Mobile Chromium exercises correction/note citations, review edits, saved attribution/reload, source navigation and discard. Hosted verification uses disposable synthetic annotations and private files; it records provider calls and removes the temporary workspace afterward.
