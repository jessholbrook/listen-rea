# AI analysis of PPTX researcher observations

This milestone combines synthesis, source-linked Q&A, and saved/reviewed answer reporting. Start by explicitly including PPTX notes or corrections in the [review-to-report workflow](pptx-followup-review.md), then create an evidence memo. These tools interpret researcher annotations. They remain separate from participant theme coding, verified PPTX passage analysis and interview follow-up generation.

## Synthesize and ask questions

In **Analysis & report**, use **Synthesize PPTX observations with AI** to propose findings over the latest included notes and corrections. The result is an unreviewed draft. Edit or remove findings, check every exact note/correction citation, review the limitations and save your review. Synthesis review and memo review are separate; review or discard synthesis before reviewing the memo or publishing a report. Regenerating, editing or discarding synthesis clears report editions, snapshots and share links and resets memo review.

**Ask about researcher PPTX observations** returns a temporary answer with source links. It does not create a saved record or alter the memo/report. The server replaces an uncited answer with the fixed insufficiency message in the report language. Unsupported, foreign, stale, invented or cross-field citations are rejected. Citation references contain the PPTX ID, exact included review version, field (`notes` or `correction`) and an exact, nonblank contiguous quote. Grounding judgments provide context but cannot be quoted as notes or corrections. Original interview questions and prepared PowerPoint slides are not evidence for these requests.

## Save, review and report an answer

**Ask and save PPTX answer draft** explicitly generates and stores a private draft. It retains the immutable original question/answer/citations and generation provenance, a frozen snapshot of cited included observations, and attributed revision history. Creating or editing a wholly private draft preserves reviewed memos and published reports. Reload after a lost save response before generating again; generation has no automatic retry or idempotency key.

Edit the saved answer, check the cited notes/corrections through source links, then review and optionally include it. Changing text or removing citations resets review and inclusion in the interface. Server inclusion requires explicit review and at least one exact citation valid against both live included observations and the frozen cited sources. An uncited insufficiency draft can remain internal but cannot enter reports. Clients cannot replace originals, sources, IDs, generation provenance or review attribution.

Only the latest explicitly included answer revision enters separate memo/report/deck appendices. Report projections contain current reviewed wording/citations, cited included source snapshots, reviewer/time, answer revision, generation provenance and whether wording/citations were edited. Private original answers and revision history are excluded. English, Spanish and French report labels preserve original-language researcher text and quotes. These interpretations do not change sample or participant-theme counts. Including, changing, withdrawing or deleting an included answer resets memo review and revokes editions, snapshots and shares. Downloaded copies cannot be recalled.

## Provider data and protocol

OpenAI receives only included notes, corrections, grounding judgments, document IDs/review versions, reporting language, and the explicitly submitted question for Q&A. It receives no original PowerPoint files, prepared slides, participant answers, original interview questions, reviewer names, source hashes, permission receipts or private revision history through these requests. Inputs and embedded instructions are treated as untrusted data. Generation uses `store:false`, a 50-second deadline, 3,000 completion tokens for synthesis and 2,000 for Q&A. Server model, prompt version and generation time accompany each result. Valid citations establish source identity; researcher review is still needed to assess interpretation quality.

Endpoints are `POST/PUT/DELETE /api/studies/:id/pptx-observation-synthesis`, `POST /api/studies/:id/pptx-observation-qa` (optional Boolean `saveDraft`, default false), and `PUT/DELETE /api/studies/:id/pptx-observation-answers`. They require workspace edit authority, exact current analysis identity/version, concept/revision scope, report language and current source/probe/prepared-snapshot fingerprints. Generation rechecks these after the provider returns before saving. Answer edits also require exact answer identity/version. Rejected requests and provider failures leave drafts and reports unchanged.

Bounds: 100 included observations / 150,000 serialized code units per request; up to six synthesis findings with 1–10 citations each; at most 20 citations per answer; 20 saved answers per analysis, 50 revisions per answer and 250,000 serialized code units across saved observation answers. Temporary Q&A remains available at the saved-record cap. Existing process-local request limits allow six synthesis and ten Q&A requests per workspace per minute. Report creation, updates, sharing, public reads and deck exports revalidate current sources and included answer projections. Participant and external API/MCP projections omit these private analysis records.

Withdrawing or changing an included source review, source erasure, response purge, exclusion, scope or language changes prevent reuse of stale results. Source erasure removes saved originals/history and synthesis with derived analyses/reports while preserving unrelated written answers. Late UI replies are ignored after navigation or source/version changes.

## Validation and next

Unit and HTTP checks cover strict request/citation validation, field/review/source identity, provider data minimization and provenance, localized insufficiency, legacy file review compatibility, human review gates, immutable originals/history, frozen sources, report projections, private-only edits, withdrawal, stale versions/scope/language, authorization, provider failures and erasure. The combined English/Spanish/French mobile workflow covers synthesis generation/review, temporary Q&A, saved drafts/reload, separate answer review/inclusion, original history, report source links, withdrawal/deletion and delayed replies after navigation. Browser generation uses marked fixtures; real hosted generation is recorded in the deployment log.

The PPTX upload, follow-up, researcher-review and AI-analysis workflows are implemented. [Research Library attachment evidence](library-attachment-evidence.md) is implemented as one milestone: cross-study search and cited Q&A over explicitly included verified excerpts and researcher observations, study/attribute/type filters, current-source drill-down and withdrawal/erasure controls. [Saved and reviewed Research Library answers](library-saved-answers.md) are implemented as one workflow: server-generated drafts, immutable originals/history, source-aware review, explicit latest-only text/CSV exports and source withdrawal/erasure. [Cross-study research briefs](library-research-briefs.md) are implemented: private editable briefs from pinned approved saved answers, exact source links, combined reviewed exports, revision/approval checks and complete dependent-brief erasure. [Reviewed transcript answers](library-transcript-answers.md) are implemented: server-generated cited drafts, immutable originals/review history, approved exports, mixed-source briefs and source-lifecycle erasure. [External recording transcription](library-recording-transcription.md) is implemented: bounded private audio/video upload, explicit audio-only transcription, draft review and approved import with provenance, retry and erasure controls. Next proposed milestone for approval: **Larger recording imports** — resumable private uploads and durable transcription jobs for full-length interviews. This extends Echo Lab’s existing keyword library; semantic retrieval, automatic scoring, email/domain setup and human pilot review remain separate.
