# Reviewed transcript answers

Research Library → **Search & ask** now includes **Ask & save draft** and a saved transcript-answer review panel. This milestone covers save/review/revise, immutable AI originals and attributed history, exact quote locations, current-source inspection, approved text/CSV downloads, and mixed transcript/attachment research briefs. English, Spanish and French notices/review controls/export warnings are supported; source quotes remain in their original language.

## Workflow and authority

Choose studies and optional exact attributes, select keyword or meaning-plus-keywords retrieval, enter a question and explicitly ask to save. Only a new server-generated answer with at least one valid exact citation can become a draft. Clients cannot submit original answers, frozen sources, model provenance or vectors. Saving requires a request ID; an exact retry replays the existing server draft without another AI call. Reusing the ID with different normalized inputs fails. Attachment and transcript answers share the workspace limit of 100 saved answers, but their normal lists and management routes remain separate. Research briefs use the authorized combined list.

A draft preserves the original answer, question, citations and model/prompt/generation provenance. Reviewers can edit the interpretation and keep/remove citations from its frozen source set. Each update appends an attributed, monotonically versioned review (maximum 20 revisions), leaving the original unchanged. Concurrent edits fail rather than overwrite. Downloads require both researcher review and explicit approval on the latest revision; approval can be withdrawn. Unsaved form edits disable downloads. Only that latest approved interpretation/citation set is exported; original AI text and earlier private reviews are omitted. Downloads already copied cannot be recalled.

## Sources, retrieval and privacy

Eligible evidence is completed, included, non-preview native response text or reviewed external transcripts in the actor’s workspace. Study/attribute filtering, exact guide/revision/concept identity, source language and external-versus-native origin are retained. Keyword retrieval remains the default; semantic retrieval uses the separately managed private index and preserves its model/version/coverage provenance when saved.

Saved generation uses at most 30 whole excerpts within 50,000 source characters, with keyword excerpts bounded to 2,000 characters each (semantic chunks are at most 1,500). Saved citations contain at most 20 exact source substrings of at most 2,000 characters each. They retain source turn IDs, actual turn number and exact UTF-16 character offsets within the original answer. For repeated text, offsets refer to the selected excerpt; semantic chunk offsets are honored. Original speaker labels remain literal source text, not verified identities. Review full responses and speaker context before interpreting a quote.

The saved-answer generation payload includes only question/output language and selected text plus study/response/turn/revision/concept/source-kind/language references. Separate names, external identifiers, attributes, file bytes and private review histories are omitted. Included text itself may contain personal information. Generation is bounded to 2,000 output tokens and 50 seconds using the shared non-stored text-generation options. Source hashes and all generation-input dependencies are derived by the server. Uncited input turns are tracked without storing another copy of their text; cited text and its original turn prompt are frozen for researcher review and export context. Query vectors remain governed by the semantic-index contract.

Every list/read/source inspection/save/export revalidates current authorized sources. Source inclusion, eligibility, attributes, revision, prompt/text or relevant import/language context changes invalidate the entire saved transcript answer, including original and every review revision. Deletion and request-driven retention use the same erasure path. Dependent briefs are removed completely, including free-text commentary and dependency references retained from removed sections. An uncited generation input is still a dependency. Storage failures are not mistaken for permanent source withdrawal. Ordinary answer review/approval changes instead block pinned brief exports until current approved revisions are selected and explicitly reviewed again.

## Briefs, exports and limits

Approved transcript and attachment answers can be combined in one brief. Transcript evidence remains typed as `transcript`, with source language/origin, original prompt, turn number/offsets and guide/concept context. It is not rendered as a verified document passage or researcher observation. Source-review fields that apply only to attachments are blank for transcript evidence; answer/brief reviewer attribution remains explicit. Text and CSV exports retain exact quotes, authenticated source links, review versions and AI/retrieval provenance. CSV formula cells are escaped. No public sharing endpoint is added.

Saved documents retain the shared 250,000-character serialized-storage bound, 100-answer workspace limit, 20-review history limit and 10-question-per-workspace-per-minute limit. Questions are 5–2,000 characters; selected corpus bounds are 100 studies and 2,000 completed responses. Current brief bounds and accumulated source-erasure dependencies remain unchanged. Transcript Q&A without saving continues to work independently, with its existing 4,000-character keyword excerpt bound.

## API

- `POST /api/library/qa`: existing question/filter/retrieval/language input plus optional `saveDraft` (default false) and UUID `requestId` (required to save). Unknown body fields are rejected. Saving returns native study/response/turn citations plus `savedAnswerId` and server provenance.
- `GET /api/library/answers`: transcript-only current saved-answer rows and editing capability.
- `GET /api/library/answers?scope=all`: authorized combined transcript/attachment rows for brief composition; each row identifies its scope.
- `GET /api/library/answers/:id`: transcript saved original, frozen cited sources and review history; internal dependency/request metadata are omitted.
- `PUT /api/library/answers/:id`: shared strict `{version,answer,citations:[{evidenceId,quote}],reviewed,includeInExports}` review contract; only exact frozen citations are accepted.
- `DELETE /api/library/answers/:id`: strictly `{version}`.
- `GET /api/library/answers/:id/export?format=md|csv`: latest-only approved private/no-store, nosniff download.
- `POST /api/library/answers/:id/source`: strictly `{id:evidenceId}`; revalidates the saved answer and returns that stored citation’s current source. This authenticated resolver also supports attachment citations in mixed briefs; it cannot fetch arbitrary supplied source references.

Existing `/library/attachments/answers` management/list/export behavior stays attachment-only. Viewers may read current answers and approved exports, but cannot generate/save/review/delete. Participants/public callers require researcher authentication; foreign workspaces cannot read or reference sources or answers.
