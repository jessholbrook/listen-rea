# External recording transcription

Research Library → **Recording transcription** supports private audio/video uploads up to **60 MiB and 60 minutes**, resumable upload parts, durable transcription checkpoints, researcher corrections/review, and a separately approved import. Drafts and partial transcripts stay out of search, Q&A and analysis. The interface supports English, Spanish and French.

## Workflow and bounds

Choose a study, title, external interview ID, recording language and file. Confirm permission to store/process the recording and send its audio to OpenAI. Uploading does not contact the provider. Supported containers are WAV, Ogg, MP4 and WebM with audio; files declared as video must also contain video. Original filenames are not stored.

The browser calculates a SHA-256 checksum and uploads private parts of at most 3 MiB, below Vercel's request limit. Each part has a fixed position, exact expected length, immutable bytes and a saved checksum. Refresh/open a pending recording and reselect the same file to resume: saved parts are skipped. File size, MIME and whole-file checksum must match the original manifest. After all parts arrive, the server checks every stored part and the complete checksum, then validates the container signature, actual decoding and duration. Only then does it expose the original recording for playback. Finalization is retryable; parts are deleted after the assembled file is committed. Neither private Blob URLs nor part storage IDs are exposed. Parts are not playable or research evidence.

Choose **Generate transcript draft** to start or resume a durable job. Each API operation processes the next five-minute audio interval and saves a checkpoint before the browser requests the next. Keep the page open to continue. **Pause after the current step** stops requesting further steps; closing/navigating away preserves completed steps. Reopen and explicitly generate/resume to continue. There is no independent background worker, cron or claim of completion while the browser is closed. Saved progress, job claims and immutable source bytes survive refresh, redeploy and function interruption. The interface shows saved upload parts and transcription steps.

Video is decoded to audio only: video frames, titles, external IDs, original filenames, study guides, participant attributes and earlier transcript text are not sent. Each request contains a fixed `recording.wav` filename, mono 16 kHz PCM audio (at most five minutes, under 10 MiB), configured transcription model and recording language. This is literal transcription without diarization, verified speaker identity, calibrated timestamps or automatic interpretation. Five-minute boundaries can split speech; human review against the original recording remains required.

Each successful step is bounded to 12,000 characters and stored privately. Steps are joined in order with blank lines only when all finish. No partial transcript enters review or research. A complete transcript is bounded to **150,000 characters** and is never silently truncated. Provider/processing failures keep completed checkpoints and original bytes. Retrying processes the unfinished step, without rerunning completed steps. A provider response lost before its checkpoint commits may need another provider call; exactly-once billing cannot be guaranteed.

Edit the complete draft, explicitly attest review, and save. The machine original/model/time remain unchanged; each revision retains text, attestation, editor and time. Editing text clears the UI attestation. Strict server inputs require the current version. At most 20 history entries, including the initial draft, and **4 MiB of serialized UTF-8 draft/history** are retained. Ordinary review requests also use the application's 250,000-character JSON request bound.

Separately approve the saved reviewed revision. This atomically creates one completed external response and transfers ownership of the assembled private media. It does not copy the recording. Reviewed text up to 12,000 characters retains one source turn; longer text is preserved in ordered sections of at most 10,000 characters so search and citations retain the complete text. Without a speaker-section review, boundaries remain storage boundaries rather than reviewed speaker turns or timestamps. Optional [speaker-section review](speaker-transcript-review.md) instead imports one source turn per researcher-reviewed section, retaining speaker/range/reviewer context. Audio attaches to the first turn; video remains authenticated import video. Provenance retains model/time, machine/reviewed text hashes, recording hash, edited flag and reviewer/time.

After approval, the pending document becomes a content-free receipt: no upload manifest, partial checkpoints, transcript, original, review history or separate recording copy. Provenance remains on the imported response. Existing source validation, saved answers, research briefs and dependent erasure apply.

## Recovery, access and erasure

Create, initialize, part, finalize and approval retries reuse exact immutable inputs. Different bytes/settings cannot replace a pending file. Delete the pending recording to start over. A workspace supports at most 20 pending recordings. Editing roles can create/upload/process/review/import/delete; viewers can inspect workspace recordings. Anonymous/participant callers and other workspaces cannot access recording metadata or bytes. Playback streams authenticated private/no-store responses, including valid byte ranges, without buffering the complete response or returning public storage URLs.

Each transcription step claims a persisted attempt/version before contacting the provider. Concurrent claims are blocked; after two minutes an interrupted claim can be retried explicitly. There are no automatic paid retries after errors. Completed steps remain saved. Each completion rechecks the current attempt, version and authorized study; deletion or a newer attempt prevents a late result from restoring content. The process-local rate limit is 20 attempts per workspace per minute. Audio decoding has a 60-second bound, provider calls 45 seconds, and each transcription step a 105-second deadline. Assembly and decoding must also finish within the hosted function's 180-second budget; very complex media can be rejected even within nominal size/duration limits.

Content-free storage guards are persisted before part/assembled-file writes. A lost acknowledgement can adopt only identical bytes on retry. Guards serialize with cleanup and check committed recording/media ownership before deleting orphan bytes. Pending deletion/expiry includes every allocated part and assembled-file ID, even an uncheckpointed write. Cleanup remains retryable if storage is unavailable. Interrupted writes retain a delayed cleanup guard so bytes written after a deletion are still erased.

Pending recordings expire after seven days or the shorter workspace retention period, with request-driven cleanup. Delete pending recordings to erase original bytes, all parts, partial job text, machine original and review history. Workspace-scoped content-free replay markers block stale creation. Imported receipts follow their response rather than pending expiry. Delete an imported response through its study to remove recording bytes, reviewed text, receipt and dependent saved answers/vectors/briefs. Copied downloads cannot be recalled.

## API

- `GET /api/library/recordings`: workspace pending recordings/receipts and editing capability.
- `POST /api/library/recordings`: strict `{requestId,studyId,title,externalId,language,permissionConfirmed:true,transcriptionPermission:true}`.
- `GET /api/library/recordings/:id`: private detail, saved part checksums/counts and completed job-step count. Internal request hashes, attempt IDs, part storage IDs and partial machine text are omitted.
- `POST /api/library/recordings/:id/upload`: strict `{version,bytes,digest,mime}`; initializes/reuses immutable manifest. `digest` is raw-file SHA-256 hex.
- `PUT /api/library/recordings/:id/part`: raw bytes, positive `x-recording-version`, zero-based `x-recording-part`; validates exact expected length. Exact committed-part retries return the current record.
- `POST /api/library/recordings/:id/complete`: positive `x-recording-version`; verifies/reassembles/decodes all parts and commits the immutable source. Exact successful retries reuse it.
- `PUT /api/library/recordings/:id/file`: backward-compatible raw upload, still bounded to 3 MiB/10 minutes; unavailable after manifest initialization.
- `GET /api/library/recordings/:id/file`: authenticated original pending media, with streaming and byte ranges. Imported media uses its response's recording endpoint.
- `POST /api/library/recordings/:id/transcribe`: strict `{version,permissionConfirmed:true}`; processes and checkpoints one five-minute interval, or produces the complete unreviewed draft after the final interval.
- `PUT /api/library/recordings/:id`: strict `{version,text,reviewed,sections?}`; saves review history. Optional sections use `{start,end,speaker,startMs,endMs}` with complete text coverage; reviewed sections require all labels and valid ordered recording ranges. Unreviewed ranges may be null.
- `POST /api/library/recordings/:id/approve`: strict `{version,reviewed:true}`; imports the latest saved attested revision once.
- `DELETE /api/library/recordings/:id`: strict `{version}`; erases pending data. Imported sources require response erasure.

The provider model uses `RESEARCH_TRANSCRIBE_MODEL` or `gpt-4o-mini-transcribe`. Successful-step usage stores only workspace/study/model/operation and interval duration, without audio/text. Provider audio handling follows its standard terms; `store:false` is not asserted for audio requests.
