# Collection review dashboard

Research Library → Collections → Open review dashboard shows current interview coverage, collection answers awaiting review, linked-brief readiness and source changes. English, Spanish and French are supported. It makes no AI calls and requires no new credentials.

## Counts and actions

- Coverage is the number of current included interviews cited by at least one current, latest-reviewed, export-approved saved answer generated with this collection. Each interview counts once. Repeated citations or several approved answers do not inflate the denominator or covered count. The per-interview count is the number of approved collection answers citing it.
- Draft answers, reviewed answers without export approval, global answers and answers generated in other collections do not contribute. Linked brief text and underlying sources never expand coverage. This is a citation-coverage indicator, not proof of complete analysis, valid interpretation, representative sampling or research quality.
- The answer queue distinguishes unreviewed drafts, reviewed answers without export approval and approved latest revisions. Review answer opens only that answer in the existing review/export interface. Returning refreshes dashboard counts. Existing source, approval, export and erasure gates apply.
- Linked briefs are separate: current/export-approved, current but needing brief review, or needing current approved pinned answers. Open a brief in the existing editor to refresh/review it. Dashboard views/checks never approve or export an answer, brief or transcript.

## Source checks and change visibility

A dashboard read creates no checkpoint. Explicitly confirm the displayed changes and choose Mark current sources checked to record a comparison point. The checkpoint stores current interview IDs and SHA-256 source-state digests, a version, timestamp, an aggregate removed count and a request-state digest. It stores no transcript, quote, member title, question, answer, notes, actor name or earlier checkpoint history.

Current sources are classified as not checked yet, added, changed or unchanged. Source-state digests cover current interview content/version/attributes/provenance/study title and associated attachment text/review version, digest and revision-time metadata. They detect version/content-state changes, not a word-level diff or an assessment of research accuracy. Unpublished imported-recording correction drafts do not change the live source until published.

Removing a previously checked interview from membership, excluding/deleting it or losing its study physically removes its ID/digest from the checkpoint. Only the aggregate previously-checked removal count remains until the next explicit check. Re-adding it is shown as added; removed identities/history are not reconstructed. Interviews added and removed before ever being checked are not counted as previously-checked removals. Deleting a collection deletes its checkpoint. Existing source/answer/brief invalidation remains authoritative; the dashboard revalidates current data before returning counts, including legacy changes that bypass normal hooks.

Source checks use an optimistic full-dashboard signature and separate collection/check versions. Source, membership, finding-review or linked-brief-state changes reject a stale submitted check with 409. The interface clears its checkbox on refresh, success and failure and withholds stale dashboard data after errors. Concurrent identical checks reuse one checkpoint/timestamp; future versions and forged checkpoint contents are rejected. A repeated check of the same unchanged dashboard reuses its original timestamp. Checking sources leaves finding approvals unchanged.

## API and scope

- `GET /api/library/collections/:id/dashboard` returns current counts and minimal interview, answer and brief metadata plus a signature and check version. No full answers, quotes, private histories or source-state digests are projected.
- `POST /api/library/collections/:id/dashboard/check` accepts strict `{collectionVersion,reviewVersion,signature,checked:true}`. The server computes all state and rejects caller-supplied checkpoint/source arrays. Existing editor roles can save a check; authenticated workspace readers can view it. Foreign, missing/deleted collections and public requests are unavailable.
- Snapshot validation, source checks and reference pruning run in transactions. The checkpoint is separate from collection metadata, so a source check does not alter collection membership, collection versions, retrieval scope or finding approvals. Existing limits remain: 200 member interviews, 30 linked briefs and 100 saved workspace answers. Current details may require review before a linked brief becomes exportable.
