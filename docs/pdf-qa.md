# Q&A over verified PDF passages

In **Analysis & report → Ask about verified PDF passages**, submit a question using the currently included PDF excerpts. This is separate from participant Q&A and researcher-annotation Q&A. It supports native extracted text and corrected OCR that a researcher has verified, selected and explicitly included in a new analysis. An OCR draft alone cannot become a source.

The explicit request sends OpenAI only the question, reporting language, selected quotes, PDF/verification/physical-page/selected-character references, and native/OCR labels. It does not send files, images, unselected text, original OCR drafts, permissions, participant answers, researcher notes, names or private history. OCR labels describe researcher verification of transcription; they do not establish independent factual verification. Questions are 5–2,000 characters; source input is bounded to 100 PDF entries and 150,000 serialized characters. Generation uses `store:false`, a 50-second deadline, 2,000 output tokens and a strict answer/citation schema. The process-local rate limit is ten requests per workspace per minute, not a durable budget.

Answers require exact contiguous quotations from a supplied selection with its exact PDF ID, verification version, physical page and selected passage start/end offsets. These offsets identify the selected passage, not a shorter quoted substring within it. The citation schema/validator is shared with PDF synthesis. Wrong document, revision, page, offsets or quote, unrecognized fields and over-limit provider outputs are rejected. Answers without citations become a fixed insufficiency message in English, Spanish or French. Citation validity does not establish that an interpretation is sound: review the original cited pages.

The prompt restricts interpretation to document excerpts, preserves uncertainty and possible OCR/reading-order errors, treats questions/excerpts as untrusted data, and prohibits attributing document text to participant experiences, identities, sensitive traits, population effects or interview counts. OCR can still contain errors after review.

## State and access

`POST /api/studies/:id/pdf-qa` accepts `{id,version,question,saveDraft?}`, plus the existing concept/revision scope query when applicable. It requires workspace edit authority, a current analysis/version/language, eligible completed/included responses and exact live selected-source fingerprints. Source, language, analysis identity/version and study data are checked again after generation in a transaction. Withdrawn/erased or changed sources cannot produce a late valid answer.

Answers remain in the current browser view and do not change the analysis, review state, report editions or share links. No answer records are stored in application documents or report projections. Provider usage is recorded without storing the question/answer as a Q&A document. Clear/reload/navigation and analysis/scope/version/language changes discard the view; delayed replies from an unmounted view are ignored. The UI provides original physical-page viewing, selected-character/verification references, source-response links and OCR labels. Use the separate saved-draft action for review and report inclusion.
