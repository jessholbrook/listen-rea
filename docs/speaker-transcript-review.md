# Speaker-aware recording transcript review

Research Library → Recording transcription now supports optional researcher-reviewed speaker sections before import. This is a manual review workflow: speaker labels and whole-section timing reflect a researcher's comparison with the private recording. They do not authenticate identities, perform automatic diarization or provide word-level alignment.

## Review workflow

Generate the complete transcript draft through the existing resumable upload/transcription flow. Edit the transcript, then choose **Create speaker sections**. Paragraphs provide initial text boundaries; long text is partitioned into bounded sections. No speaker or timing is inferred.

Select a cursor position in a section's read-only text and choose **Split at selected cursor**. Merge with the following section when needed. Splitting/merging clears affected timing fields. Enter a speaker label and start/end seconds, and use **Play reviewed section** to compare with the original audio/video. Text remains in the main editable transcript; changing it clears the current section map and review attestation. Changing labels, boundaries or times also clears the review checkbox.

Incomplete section labels/times can be saved in an unreviewed revision. Reviewed saves require every section to have a nonempty label and a complete, ordered, nonoverlapping range inside the decoded source duration. All sections must cover the exact complete reviewed transcript once, in order, without gaps or duplicated text. UTF-16 text boundaries cannot split Unicode surrogate pairs. Whitespace-only sections are rejected. Limits: 200 sections, 80 characters per label, 12,000 text characters per section; the recording workflow's 150,000-character transcript, 20-history-entry and 4 MiB UTF-8 history bounds still apply. The initial section builder respects the 200-section limit even with many paragraphs. Simultaneous overlapping speakers cannot currently be represented with overlapping playback ranges.

Save an explicitly reviewed revision, then separately approve import. Original machine text/model/time stay unchanged. Earlier review revisions retain their section map, editor, time and attestation while pending. Import creates one source turn per reviewed section, retaining exact section text and server-owned media ID/type, speaker, range and reviewer/time. Clients cannot supply media identifiers or reviewer provenance. Imports without sections keep the previous behavior. A content-free receipt replaces all pending text/history/maps/checkpoints after approval.

## Source playback and citations

Imported source turns, keyword results, cited Q&A, saved transcript answers and research briefs display the reviewed speaker and recording interval. Expand the citation to play the authenticated private audio/video range. Playback seeks to the section start and pauses at its end. These are section ranges: the exact quoted words can occur anywhere inside the range. Full recording playback remains available in the source view.

Keyword ranking includes reviewed speaker labels. Semantic chunks preserve the same current source metadata. Transcript Q&A sends only speaker/range context alongside selected evidence; media IDs and reviewer identifiers are excluded from the model payload. Citation labels/ranges returned to clients are attached from current server evidence, never model-proposed metadata. Saved answers freeze exact text offsets, section context and source dependencies; idempotent draft replay preserves that context.

Approved answer/brief text and CSV exports retain the label, start/end milliseconds, recording link and reviewer/time. Recording links require the existing workspace session and do not expose private Blob URLs. The original response/turn citation remains available alongside the recording link. Viewers retain read-only access; existing editor, study and workspace boundaries apply.

## Changes and deletion

Any current source change to section metadata, text or linked audio invalidates dependent saved answers, embeddings and briefs through the existing source lifecycle. Pending erasure removes all section maps and history with the recording. Approved response erasure removes turns, speaker/range/reviewer metadata, source bytes, import receipt and dependent research. Copied downloads cannot be recalled. Corrections after import use [private source revision drafts and explicit reviewed publication](imported-recording-revisions.md); the original recording is preserved while dependent research is invalidated.

Verification covers complete-text/Unicode/timing/label validation, partial unreviewed saves, strict server-owned provenance, role/workspace/version checks, keyword and semantic metadata, minimized model payloads, forged citation metadata, saved-answer replay, answer/brief exports, source-change invalidation and physical erasure. Mobile English/Spanish/French checks exercise splitting, labeling, timing, review/import and private range playback. Provider fixtures are explicitly marked; these checks do not establish human attribution or transcription accuracy. See [deployment evidence](vercel-deployment.md).
