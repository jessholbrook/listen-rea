# Reusable review plans

Open **Research library → Review inbox → Open handoff packet → Internal handoff review → Reusable review plans**. Plans are also available in the original saved handoff editor. English, Spanish and French controls support creating, editing, deleting, previewing and applying workspace templates. No email service or domain is needed.

## Saving and applying

An editor can save up to 50 named plans per workspace, each with 1–10 unique current workspace editors. Each reviewer has an optional offset of 0–365 calendar days from a chosen start date. A blank offset means no deadline. Zero means the start date itself. Dates use calendar arithmetic, including leap years, rather than elapsed 24-hour intervals. The initial start date is the browser's local calendar date; explicit dates and resulting deadlines must stay between 2000-01-01 and 2100-12-31.

Choose a saved plan and start date, then select **Preview plan**. The preview lists every reviewer and their concrete date (or no deadline). Previewing and cancelling make no changes. Applying requires acknowledgement that it replaces the packet's entire requested-reviewer list and deadlines, clears all reviewer decisions and final packet approval, and retains existing comments and resolution state. Applying the same plan again intentionally starts review again; an old request cannot be replayed. No template can approve research or skip the packet's ordinary reviewer, comment-resolution and explicit final export gates.

Creating or editing a template does not change existing packet requests. Deleting a template also leaves requests already copied into packets intact. There is no automatic synchronization or reassignment. If a saved reviewer becomes unavailable or loses edit access, application is blocked until the plan is edited. Unavailable reviewers display without a retained name; editors can remove them and select current members.

## Concurrency, privacy and erasure

Plans contain only a name, reviewer IDs, optional day offsets and coordination version/identity metadata. They contain no findings, summaries, research links, transcripts, comments, email addresses, approval decisions or copied member names. They belong to the authenticated workspace. Readers can list plans; only admins, researchers and collaborators can create, edit, delete or apply them. No public participant or shared-report endpoint exposes them.

Plan edits/deletion require the current template version. Application checks the current template version, original packet generation, packet version, review version, content signature, current editor membership, calendar bounds and explicit acknowledgement inside the packet transaction. Dates and reviewer lists are computed on the server from the saved plan. Stale previews, deleted templates, source changes, replacement packets and unavailable reviewers fail without partially changing assignments. Applying never retries automatically. Existing packet dependency tracking and source erasure rules remain in force.

Packet/source/collection deletion erases that packet's applied requests, dates and comments. The reusable coordination-only template survives because it does not contain or depend on that research. Explicit template deletion erases the template. Workspace cleanup includes all plan records. Template names are user-authored coordination labels; avoid putting research findings or participant details in them.

While editing a plan or confirming its preview, adjacent packet and feedback actions are locked. Unsaved packet, reviewer, deadline or comment changes must be saved first. A mutation error clears the displayed template list; refresh the packet before continuing. There are no background jobs, provider calls, external notifications or live email delivery in this feature.
