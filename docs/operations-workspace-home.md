# Operations workspace home

Open **Research library → Operations home**. The workspace launchpad combines personal and team pinned views, quick report links and current follow-up priorities with the existing research/review overview. English, Spanish and French controls are available on mobile.

Choose a saved view in **Saved workspace views**, then choose **Pin for me** or, for an eligible shared view, **Pin for team**. Each list holds up to 12 distinct views. Personal pins can reference your private views or any shared views you can access; each member controls their own list, including readers. Workspace editors control the common team list, which accepts only shared views. Pinning never changes the underlying view’s visibility, creator or permissions.

Pinned views can be opened, moved up/down or removed. Order persists across sessions. Opening checks the current saved view version and visibility before navigating to the original review, task, workload or report screen. Report pins restore settings only; they still require a new report preview and review before download. A missing, deleted or newly private view is removed from any list that can no longer access it when the boards load. That cleanup advances the board version. A departed member’s personal list is pruned; the team list survives. Source erasure removes current tasks and priorities, but an accessible saved configuration can remain pinned with its exact now-empty scope.

Quick report links open workload or activity report settings with the current Operations language and browser time zone. They do not generate a report, acknowledge its scope or download a file automatically.

Follow-up priorities show unfinished tasks due today, unassigned unfinished tasks and the current member’s unfinished tasks. Categories can overlap. Every count opens the full original queue with its exact assignee/status/date filters. Completed tasks are excluded; dates use the viewer’s local calendar and update at the minute tick or window focus. Refresh loads changes from other sessions. Existing overdue/review counts, blockers, recent activity and saved-view management stay available below the launchpad.

The authenticated pin endpoint is **GET library/operations-pins** and **PUT library/operations-pins/private|shared** with a current board version and ordered distinct view IDs. Strict schemas reject extra authority/content fields, invalid IDs, duplicates and more than 12 entries. Every write checks current membership, and team writes require both authenticated and current database edit access. Concurrent stale writes fail instead of silently reordering another member’s changes. No-op writes preserve versions and timestamps. Failed responses clear the loaded home and require explicit refresh, with no automatic write retry.

Pin records store only view IDs, owner/scope, version and timestamps. Names, visibility and settings are resolved from current saved views; task/source/report content and approval state are never copied into pins. Other users’ personal lists are not exposed, even to admins. Overview queues/catalog and pin boards load together; failure clears the complete view rather than leaving stale cards. The existing report/source checks remain responsible for fresh results. No external provider, email/domain setup, migration or environment variable is required.
