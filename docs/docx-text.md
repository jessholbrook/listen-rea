# Verified DOCX text selections

After a participant submits a DOCX with an answer, **Responses → DOCX text and verified passages** lets researchers select exact text from numbered prepared paragraphs. The original Word file is not retained; references are to the immutable prepared body-text snapshot described in the [upload contract](participant-docx.md), not Word page numbers or original paragraph IDs. Preparation can omit structure or context. Verification records a researcher's selection review, not the truth of a document claim.

Choose a paragraph, select text and add the passage. At most ten passages of 1–1,000 UTF-16 code units each can be saved. Exact duplicate ranges, blank quotes, invented text, foreign paragraphs, invalid offsets and boundaries inside a Unicode surrogate pair are rejected. Different occurrences of repeated text have different character ranges. Browser citations show one-based inclusive character positions; stored offsets are zero-based with an exclusive end, matching textarea selection. Paragraphs and quotations retain their original language.

An unchecked attestation confirms comparison with the cited prepared paragraphs, including removals. Changing the selection resets attestation. Saving appends a private revision with server-attributed researcher ID/name, timestamp and the exact passages. Empty selections withdraw the current selection while preserving earlier revisions. History is capped at 50 revisions. View-citation controls reopen the exact paragraph and highlight its character range. Reload restores the saved revision; stale edits must reload before retrying.

## Source and access contract

`GET /api/studies/:studyId/participant-docx/:docxId/text` returns prepared paragraphs, source/digest fingerprints and the private verification record or null. It creates no verification record. `PUT` requires edit authority, exact current source/digest/version, literal `attested:true` and strictly validated passages. Other methods are unavailable. No client-supplied reviewer, timestamp, history or arbitrary metadata is accepted. An optional strict Boolean `includeInReports` defaults to false; an included selection must be nonempty.

The snapshot digest hashes the exact JSON paragraph array. A separate source fingerprint binds that digest, original-byte digest, DOCX metadata, response/turn identity, question and written answer. Saved records retain those fingerprints and response/turn references; a citation's full identity is the file ID, source/digest, verification revision and paragraph/character range. A matching quote in a different paragraph or changed source cannot reuse an earlier verification. Conflicting writes serialize and only one succeeds. Read-only workspace members can read, but cannot save; anonymous, foreign-workspace and participant-token access to verification is rejected. Draft files cannot be verified.

Prepared text is read through private storage and returned under no-store access. Browser display remains escaped plain text. Verification makes no provider calls. Raw paragraphs and verification history remain private. Only the latest [explicitly included selection](docx-evidence.md) and reviewer attribution enter new report appendices; participant payloads and external API/MCP DTOs exclude them. Private-only revisions preserve reports; saving or withdrawing inclusion revokes analyses, editions and share links. The general DOCX quality/notes review remains separate.

File erasure removes prepared text, review and verification history, revokes derived reports and blocks late writes while preserving written answers. Whole-response deletion/retention purge also removes verification history. Related image/PDF source erasure that redacts a DOCX turn's prompt clears its verification; fresh selection/attestation is required against the new source.
