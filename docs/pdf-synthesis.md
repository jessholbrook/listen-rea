# AI synthesis of verified PDF passages

First [verify and explicitly include PDF passages](pdf-evidence.md), then create an analysis. In **Analysis → Synthesize verified PDF passages**, choose **Synthesize PDF passages with AI**. This is a separate, explicit researcher action. Existing participant theme coding, Q&A and image-observation synthesis do not start PDF synthesis or receive PDF excerpts.

The model receives only reporting language, PDF IDs, verification versions and selected passage text with physical page/start/end references. Full documents, unselected extraction, descriptions, interview answers, private verification history, reviewer names and workspace/response identifiers are omitted. The server requests non-stored structured generation (`store:false`), with a 50-second deadline, a 3,000-token output cap and a workspace rate limit. This is a request setting, not a claim about provider-wide retention policies.

Each proposed finding must cite a supplied PDF/verification version, physical page and exact passage reference range. Citation wording must be an exact contiguous substring within that selected passage. Wrong versions/pages/ranges, fabricated or combined quotes and missing citations are rejected. Up to six findings are permitted; no findings with an explanation of insufficient evidence is valid. Titles, descriptions and limitations use the reporting language while quotes keep their original wording. Embedded instructions in excerpts are treated as untrusted data. These controls verify citation identity, not interpretation quality or the factual accuracy of document claims.

Generated synthesis starts as **Draft · review required**. Compare each interpretation with the cited page, edit or remove findings, review limitations, then check the review statement and **Save PDF synthesis review**. Content edits in the UI reset its review checkbox. Model, prompt version and generation time are server-owned; review attribution/time come from the signed-in researcher. The cited-page button uses the private viewer and the source link opens its transcript. Empty findings can still be reviewed to document insufficiency.

Review or discard the synthesis before marking the memo reviewed, creating an edition, sharing or exporting a presentation. Only reviewed synthesis is appended to memo downloads/shares, report text and presentation exports. Report editions retain a separate immutable synthesis snapshot; API clients cannot replace its provenance. The synthesis is labeled as interpretation of selected document excerpts, not interview statements or independent fact verification. It does not change participant counts or participant-answer theme coding. External REST/MCP projections and participant responses do not gain synthesis text automatically.

Generate, regenerate, save review and discard all advance the analysis version, clear memo review and remove existing report editions/snapshots and share links. Re-review the memo and create a new edition after changes. The server checks the current analysis, response-set version, reporting language and exact included source evidence again after generation, before saving. Concurrent edits, source withdrawal or erasure cannot commit a stale synthesis. Existing PDF/source deletion and inclusion-withdrawal cleanup also remove synthesis with the analysis and derived reports. Already-fetched or downloaded copies cannot be recalled.

Validation includes exact PDF/page/range/version/quote checks, empty findings, minimal provider payload and non-stored bounded generation, malformed/unavailable providers, publication review gates, immutable provenance, exports, discard and withdrawal. Browser checks exercise editing/review, actual cited-page pixels, transcript navigation, report display and invalidation on discard. Synthetic automated checks do not establish interpretation quality; human pilot review remains deferred.
