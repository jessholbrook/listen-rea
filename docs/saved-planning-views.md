# Saved planning views and deadline reports

Open **Research library → Action center → Follow-up calendar**. **Saved planning views** stores a named calendar scope; **Operations report → Saved reporting views** stores reusable deadline-report settings. English, Spanish and French controls support mobile, including long translated saved-view actions.

Planning settings include the exact collection, assignee, task status, title search, month, selected day/window, language and report time zone. “Assigned to me” resolves for the current viewer, including when a shared view is opened. A saved month or day stays fixed; overdue, next-seven-day and undated queues resolve against current results when opened. On-screen priorities use the viewer’s local date. Reports compute their reference date in the explicitly chosen report time zone and show that date and zone in the preview. Opening a saved setting restores language and report time zone but never restores selected tasks, a rescheduling draft, report rows, a preview signature or acknowledgement.

Use **Save current view**, choose private or workspace-shared visibility, then save the name. Applying, copying, updating and deleting reuse the existing saved-view permission and current-version checks. Private views belong to their creator and stay invisible to other members, including admins. Shared views are visible to the workspace; their creator or an eligible admin can manage them, and only the creator can change visibility. Readers can create private views/copies and generate reports, with no shared-view or task-edit authority. Existing combined limits remain 25 private views per member and 50 shared views per workspace across all saved-view kinds.

Open planning and deadline-report settings from the Operations home saved-view chooser or pin them for personal/team access. Personal pins accept your accessible private/shared views; team pins accept shared views and require an editor. Opening rechecks the saved view version and visibility before navigation. Pinning does not change its visibility or approve a report. A stale saved view requires refresh rather than silently applying new filters. Missing collection/member IDs remain exact unavailable scopes; applying them never widens a queue.

To export deadlines, set the calendar filters, choose the report time zone, generate a preview and review its scope. Reports include every matching task, up to 1,000 rows and 2 MB, independently of the agenda page. Each row includes due date or the undated label, current collection/title/assignee/progress, overdue status as of the report date, task version and exact collection/task IDs. CSV neutralizes spreadsheet formulas in user-authored fields; text exports flatten control separators. Source research, private review text and member email addresses are not included. Downloads are copies and cannot be recalled after research is later erased.

Previewing and downloading use the existing authenticated stateless report endpoints and do not change tasks, activity history or handoff approval. Downloads require explicit acknowledgement and a matching fresh fingerprint of the current actor/workspace/role, settings, scope metadata and report rows. Date/task/version/name/role/filter or source changes that affect the report reject the old preview and require regeneration. The reference date also participates in the fingerprint, so date rollover cannot silently reuse yesterday’s relative deadline report.

Saved-setting drafts and report previews lock conflicting filters, navigation and language controls. A report preview also disables rescheduling. Rescheduling hides the report controls and retains its original reviewed date-change workflow. Failures clear stale catalog/preview state, release controls for explicit recovery and never automatically retry mutations or downloads. Source erasure removes linked task rows and invalidates populated exports while preserving accessible planning/report configurations and pins with their exact empty scopes. Settings cannot recreate deleted research or approve an old report.

Calendar settings use the existing `library/saved-review-views` store with strict `calendar` and `report_calendar` configurations. Dates/months, selected-day consistency, assignees, status, language and time zone are validated. Schemas reject paging, task selections, rows, signatures, acknowledgement, authority fields and invalid dates or scope values. The existing pin and report services remain authoritative; no new migration, environment variable, external provider or email/domain setup is required. Scheduled reports, outbound reminders and external calendar synchronization remain outside this bundle.

Validation covers exact settings persistence, strict schemas, privacy/roles/reader copies, cross-session versions/pins, all three report languages, current scoped rows and formula-safe exports, unchanged task/history/review records, stale-preview rejection, unavailable scopes, source erasure and oversized reports. Mobile flows cover month/day/assignment/language/time-zone restoration, draft/report locks, actual reviewed downloads, pinned navigation, fresh report reopening, reader copies and recovery from stale views or changed/erased rows.
