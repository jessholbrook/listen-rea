# PDF text extraction and verified passages

In **Responses → participant transcript → PDF text and verified passages**, choose **Extract PDF text**. This reads the prepared PDF from private storage on the server and saves one text string per physical PDF page. It does not contact an AI provider. Blank or scanned pages show **No extractable text**; [researcher-triggered OCR](pdf-ocr.md) is available as a separate authorized action with human verification. Printed page labels may differ from the physical PDF page numbers used by citations.

Choose a page, select up to 1,000 characters in the read-only extracted text, then **Add selected passage**. Up to 10 passages can be saved per PDF. **View cited page** opens that physical page in the existing private canvas viewer. Compare wording and reading order with the actual page, check the verification statement, and choose **Save verified passages**. The verification statement is required even when withdrawing every passage. Unsaved selections are drafts; **Reload saved verification** explicitly discards them.

Each citation retains its physical page number, exact extracted quote and zero-based UTF-16 start/end offsets (end exclusive). The server requires an exact match against its saved extraction; client-supplied wording, page changes, duplicates and stale source/digest/version submissions cannot substitute evidence. Saved verification snapshots record the authenticated researcher and time, retain removals, and preserve up to 50 revisions. Concurrent saves reject the stale editor. Extraction retries return the same saved extraction without overwriting verification. Verification is an accountable human judgment, not an automatic assertion that extraction matches the original visual layout.

Extraction binds to the stored file digest, PDF metadata, interview, turn, prompt and answer. It runs in a separate Node process with only PATH/NODE_ENV, a 15-second deadline, 128 MB V8 old-space cap and bounded output. Limits are 20,000 characters per page and 200,000 per PDF; over-limit documents fail without a partial extraction. These bounds are not an OS sandbox or total-memory guarantee. The pinned PDF.js legacy worker and its Node canvas dependency are traced into the hosted function. Extraction reads page text only; it does not run an annotation/action layer or perform OCR.

Only authenticated members of the source workspace can read extraction/history, and existing edit roles can extract or verify. Submitted answers are required; draft PDF attachments cannot be extracted. These records are separate from participant responses and public/external API/MCP projections. Raw extraction, descriptions and PDF review notes do not enter model prompts or interview follow-ups. A separate [explicit PDF synthesis request](pdf-synthesis.md) sends only included, verified excerpts and their page references. [Optional participant PDF questions](participant-pdf-ai.md) independently extract bounded page text with separate participant permission; they do not use or imply researcher passage verification. [Explicitly included verified passages](pdf-evidence.md) can now appear in analysis/report appendices, shares and exports.

Individual PDF deletion, whole-response erasure and retention remove extracted pages and all verification history along with PDF reviews/files. Deleting a related image-generated question also resets PDF extraction/verification tied to the old prompt context while preserving its PDF and written answer. Source checks prevent a stale extraction finishing after erasure or source change from recreating that evidence. Previously downloaded/fetched content cannot be recalled.

Validation covers real two-page extraction, blank/invalid inputs, exact page/range validation, duplicate rejection, attestation, source/digest/version checks, concurrent corrections, participant/workspace isolation and individual/whole-response cleanup. Mobile Chromium checks select actual extracted text, open and render the cited page, save/reload/withdraw verified passages and inspect attribution/history. Existing English/Spanish/French participant attachment controls remain supported; the internal researcher verification panel is English.
