# Collection follow-up plans

Collection review dashboards now include internal follow-up plans in English, Spanish and French. From **Research library → Collections → Open review dashboard**, choose **Add follow-up**, or **Plan follow-up** beside an interview, collection answer or linked brief.

## Workflow

- Create a short task title, optionally assign a current workspace member and choose a due date. Tasks can be open, in progress or completed; reopening clears the completion timestamp. Only existing editor roles can change tasks. Workspace readers can view them.
- Filter all tasks, assigned to me, unfinished, completed or overdue. Unfinished tasks due before the browser's current local calendar day are overdue; due today is not overdue. Due dates are date-only values from 2000 through 2100, without time-zone conversion or notification scheduling. Tasks without a date are never overdue. Unfinished tasks appear first, sorted by due date, then creation time.
- Link to an interview currently in the collection, an answer generated with that collection, or a currently linked brief. Open linked research through existing authenticated source, single-answer review or brief views. Research links are fixed after creation; delete and create a new task to change them.
- Completion records task progress only. It never checks sources, approves transcripts/findings/briefs, changes export permission, or claims research completeness. No reminders or email are sent; no provider/domain setup is required.

## Lifecycle and access

Task titles are researcher-authored, with no automatic copying of transcript text, answers, quotes or target titles. The server stores current task state only, including current assignee ID and optional source reference; no task edit history, comments, attachments, assignee name/email copies or original-title copies. General collection tasks have no source dependency: use them for coordination, and link research-related tasks to preserve source-removal behavior.

Collection deletion removes all its tasks. Interview removal/exclusion/erasure removes interview-linked tasks; answer disappearance removes answer-linked tasks; brief unlink/deletion removes brief-linked tasks. This includes completed tasks and all their authored title text. Existing source corrections invalidate dependent answers/briefs and their linked tasks. Interview-linked tasks stay attached to the current included interview through corrections. Membership changes invalidate scoped answers and therefore their linked tasks through existing dependency rules. Removed/moved assignees are cleared, with a task version increment. Revalidation occurs within the collection lifecycle and again before task access; foreign workspace objects cannot be linked or assigned.

A content-free SHA-256 workspace/request digest and creation timestamp prevent deleted requests from recreating task text. These markers contain no collection/source/task IDs, titles, names, or due dates, and are retained without expiry. They are not displayed as a task history.

## API and limits

- `GET /api/library/collections/:collectionId/tasks`: current task views, current workspace member IDs/names, current user ID and edit capability. No member emails, workspace IDs, input hashes or request IDs are returned.
- `POST` at the same route: strict `{requestId,title,assigneeId,dueDate,status,target}`; target is `null` or strict `{kind:"interview"|"answer"|"brief",id}`. Calendar dates must be real dates. At most 100 tasks per collection, including completed tasks. Titles are trimmed, 3–160 characters.
- `PUT /api/library/collections/:collectionId/tasks/:taskId`: strict `{version,title,assigneeId,dueDate,status}`. Exact current-content retries reuse current state; divergent stale or future versions return 409. The source link cannot be edited.
- `DELETE` at that route: strict `{version}`; stale deletes return 409.

Creation uses a workspace-scoped request UUID and a hash of initial content, collection and target. Exact retries return current state; reuse with changed input returns 409. Source checks, permission checks, task mutations and dependency pruning run transactionally. Deleted task edits return 404; deleted request replay returns 409. UI errors clear the displayed plan/editor until refreshed, avoiding stale edit actions.
