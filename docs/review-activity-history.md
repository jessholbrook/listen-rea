# Review activity history

Open **Research library → Review inbox → Review activity history**. All authenticated workspace members, including readers, can inspect current packets' recent coordination history. English, Spanish and French controls are available. History starts recording new actions with this release; existing packets are not backfilled with invented events.

## Recorded actions and display

Successful packet creation/edits, reviewer assignment/reassignment, deadline changes, review-plan applications (including batches), reviewer approval/withdrawal, comment addition/resolution/reopening/deletion and final approval/withdrawal record an event in the same transaction as the change. Each event records a server timestamp, actor ID, action, original packet identity, current coordination versions, relevant reviewer/date changes, decisions cleared and whether final approval was reset. Comment events contain no comment ID or body. Plan events contain actual reviewer/date changes, not copied template names or research.

When current-context validation clears decisions or final approval, it records an automatic event with the affected reviewer IDs. Automatic validation is attributed to the system rather than whichever person opened a screen. Packet edits record their editor without copying any changed text; subsequent automatic review invalidation can appear as a separate event. A failed or stale user mutation does not create a user action. Normal stale-source validation may still commit a real automatic invalidation before rejecting a mutation. Exact retries, no-op saves, unchanged reads and repeated approvals do not append duplicate events.

The history uses current packet/collection titles and current workspace member names when displayed. It never stores those titles or names in event records. Renaming a member changes how their earlier actions are displayed; moving or removing them from the workspace masks their display name. IDs remain available for matching an unavailable person until the owning history is erased. This is recent coordination history, not an immutable audit trail or a historical directory of personal names.

## Filters and navigation

Filter by packet, person involved, action and inclusive local calendar dates. Person matches the actor or a reviewer explicitly recorded in the event's before/after, decision or reset information. **Automatic validation** selects system events. The browser sends its current time zone so date filters and displayed timestamps use the same local calendar, including leap days and daylight-saving boundaries. The read API defaults to UTC if no time zone is supplied. Calendar inputs are validated real dates between 2000-01-01 and 2100-12-31, and the through date cannot precede the start date.

Server-side pagination returns 20 matching events per page, ordered by newest timestamp, packet identity and descending per-packet sequence. Sequences preserve ordering when events share a timestamp. Filters intersect and reset pagination. **Open handoff packet** opens the original generation in the normal editor; closing it refreshes current state and retains the selected history filters. A deleted packet/person scope stays an explicit unavailable selection and is never silently widened. Refresh clears stale rows while loading; failed loads show an error until a successful refresh or filter change.

The view retains up to 100 recent events per packet, within a 200,000-character record bound. Older events are removed and counted. The displayed omitted count describes older events discarded for the selected current packet(s); those events cannot be assigned to person/action/date filters after removal. Matching counts describe retained events only. There is no workspace-wide archive, email notification, permanent audit guarantee or historical export in this feature.

## Privacy and lifecycle

`GET library/review-activity` is authenticated, workspace-scoped and read-only. It strictly validates packet/person/action/date/time-zone/page parameters, rejects duplicate or unknown parameters, and validates current research/feedback before projecting activity. Readers can inspect history but gain no new mutation permissions. Public participants, shared reports and foreign workspaces cannot access it.

Stored records contain coordination IDs, dates, counters, action codes and approval-reset facts only. They contain no research summaries/findings/transcripts, attachment text, comment bodies, copied names/titles, email addresses, provider output, template names, approval signatures or internal comment request hashes. Display responses resolve only current workspace names and current original packets. They do not alter normal reports, research exports, approvals, packet versions or review signatures.

History belongs to the original packet generation. Packet/source/collection removal erases its complete event record through the same dependency cleanup as feedback. Orphan pruning also removes event records whose original packet no longer exists. A replacement packet starts a new history and cannot revive an old generation. Workspace cleanup removes all owned event records. Template deletion leaves already-applied packet coordination/history intact, since no template text was copied.

No new service, environment variable, provider call, domain or email setup is required. Human pilot/interpretation review awaits the approved interviews; domain-dependent live email remains deferred.
