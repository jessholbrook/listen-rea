# PPTX upload-to-report workflow

This milestone combines private presentation uploads, prepared slide text, researcher passage verification and explicitly included report evidence. Enable **Allow optional participant PPTX attachment** on an open guide question, save and publish. The setting freezes in admitted sessions; later guide edits do not enable it for existing interviews. Changing a question type clears the setting, and non-open questions cannot publish with PPTX uploads enabled.

Participants choose a PPTX, describe it and check an initially unchecked sharing permission before uploading. Uploading is optional and does not submit the written answer. English, Spanish and French controls support reload, removal and exact retry after a lost upload response. Drafts bind the file digest, description, upload ID and exact interview version; retries cannot substitute a different file or description. Submit the exact current attachment with the answer or remove it first. Submitted files can be erased only by an authorized researcher; written answers survive erasure. Pending answer saves and stale versions block attachment changes.

## What is prepared and retained

Only a private JSON snapshot of slide text and metadata is retained. Original PPTX files, filenames, images, speaker notes, comments, document properties, master/layout text, link destinations and embedded content are not retained. No Office renderer, script execution, relationship fetching or provider request runs during preparation. Native shape and table text follow the presentation's declared slide relationship order, rather than ZIP filenames. Hidden slide/shape flags are respected; omitted or empty slides keep their original numbered slots. At least one readable included slide is required. Text-only preparation does not reproduce layout or establish visual visibility beyond recognized hidden flags. Charts, SmartArt and image-only content are not transcribed; use the prepared text to decide whether a passage is usable.

PPTX MIME is required; legacy PPT, encrypted and macro-enabled files are unsupported. The original upload is capped at 3 MiB, with 1–100 slides, up to 2,000 text paragraphs and 200,000 UTF-16 text code units. ZIP validation bounds 1,000 entries, 2 MiB per entry and 20 MiB total declared expansion, rejects duplicate/unsafe paths, encrypted entries, unsupported compression and macro/ActiveX/embedded-file entries, and checks local headers and CRCs for parsed parts. Empty embedding directories used by normal PowerPoint files are allowed. Parsing rejects malformed UTF-8/XML, DTDs, processing instructions, excessive nesting/nodes and missing, duplicate, external or unsafe slide references. A separate Node process receives no application credentials, has a 96 MiB heap limit and an eight-second deadline, and writes only a strict versioned snapshot. These bounds intentionally exclude oversized or complex decks.

Private viewing and prepared-text download use authorized study/interview routes, `private, no-store`, `nosniff` and a sandbox CSP. External relationships are never opened. There is no original-file download or slide rendering in this milestone.

## Verify and include slide evidence

In a response transcript, select exact text from a prepared slide, add the passage, check it against the source and attest to the selection. Verification captures document/response/turn/source fingerprints, prepared-text digest, exact slide number and UTF-16 character range, quote, reviewer, time and revision. Offsets cannot split a surrogate pair. Up to ten distinct nonblank passages of at most 1,000 code units each are allowed per selection; history is limited to 50 revisions. Stale source/digest/version writes fail and require reload. Participants cannot read researcher verification; read-only users cannot save it.

Inclusion is off by default and separate from verification. Include at least one verified passage to project the latest selection into **Verified PPTX passages** appendices in the analysis, shared/exported memo, report editions and editable deck. Only completed, eligible responses in the exact current revision/concept scope qualify. The server constructs and revalidates projections; client fields cannot forge source quotes or reviewer metadata. English, Spanish and French labels preserve source-language quotations. Authorized source controls highlight the exact selected range and link back to the response. Private verification history, unselected slides and omitted content stay out of reports. Up to 100 evidence records / 150,000 serialized code units are accepted per analysis.

These are researcher-verified document excerpts, not participant quotations or independently established facts. They do not change participant or theme counts. Uploading and verification do not invoke AI; ordinary analysis continues to use written interview answers. [Optional PPTX-aware interview follow-ups and researcher reviews](pptx-followup-review.md) require the frozen guide setting and separate per-upload participant permission for interview AI. [PPTX evidence AI analysis](pptx-evidence-analysis.md) supports explicit synthesis, Q&A and saved/reviewed report answers over included excerpts.

## Changes, withdrawal and erasure

Saving an included selection, changing it or withdrawing it removes derived analyses, report editions, snapshots and share links. Later wholly private verification edits preserve current reports. Sharing, edition changes, public reads and deck export revalidate the latest included sources. File deletion removes prepared text, metadata and verification history, invalidates reports and preserves unrelated written answers. Whole-response purge/retention removes associated storage and verification through the existing deletion queue. Removed draft upload IDs are tombstoned so retries cannot restore them. Downloaded report copies cannot be recalled.

If an image, PDF or DOCX question source is erased, independent PPTX drafts survive and bind the new interview version; stale answers are rejected. Context-bound PPTX verification is cleared when a related question is redacted. PPTX file metadata and researcher verification/evidence are omitted from external API/MCP projections. Private source viewing is also available from the authorized research-library response view.
