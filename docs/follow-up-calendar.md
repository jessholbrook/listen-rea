# Follow-up planning calendar

Open **Research library → Action center → Follow-up calendar**, or use the calendar shortcut on **Operations home**. English, Spanish and French controls work on mobile.

The month grid shows matching task counts on each day. Choose a day to narrow the agenda; choose it again or **Show whole month** to see the complete month. Previous/next month, a month picker and **Current month** support planning from January 2000 through December 2100. Month grids start on Monday. Dates are date-only values; arithmetic and translated date labels preserve the stored day across time zones, daylight-saving changes and leap years. Today follows the viewer’s local calendar and updates on the existing minute tick or window focus.

Collection, assignee, task status and title search intersect across the grid and agenda. Unfinished is the default. Status filters can include completed tasks in month counts and agendas. Priority buttons show unfinished overdue, due-today, next-seven-calendar-days and undated work; selecting one switches to unfinished status. The seven-day window includes today and excludes the seventh following date. Undated work has its own agenda. Empty or unavailable collection/member scopes never widen to another queue. Agendas paginate at 20 tasks. Opening a task reloads its exact ID and collection in the existing action center, with current permissions and no title-based substitution.

Editors choose **Reschedule due dates** to enter the existing reviewed bulk-update workflow. Select up to 25 exact task/version coordinates, including across days, months, filters and pages. The selected list remains visible and a hidden-selection count identifies tasks outside the current window. Choose a new real calendar date or clear the deadline. Calendar rescheduling always keeps assignment, task title, progress, completion and source links. No drag-and-drop writes occur.

Preview shows each current before/after value and availability without changing tasks. Applying requires acknowledgement. Each ready task is checked and committed independently at its current version, so a stale or unavailable task does not prevent other ready tasks from saving. No-op rows preserve versions and history. Real date changes retain the existing task-activity attribution and stale the handoff review/final approval; they do not approve research. Existing triage APIs remain authoritative for workspace membership, edit roles, valid dates, strict bounded inputs and source checks.

Selection or date drafts prevent action-center mode/language changes and refresh. A prepared preview or interrupted response also locks calendar filters. Cancel or finish explicitly refreshes current data while retaining the calendar scope/month/day. An interrupted response may have committed a change: inspect refreshed task state before trying again. Writes are never retried automatically. Readers can browse and open current tasks, with no rescheduling controls or write authority. Source erasure removes linked tasks, counts and retained history; applying an older preview cannot recreate erased work.

The calendar reads the existing authenticated action-center projection. It creates no calendar records, source copies, provider calls, environment variables, migration or email/domain requirement. Saved planning settings and reviewed deadline exports are available through [saved planning views](saved-planning-views.md). The calendar does not send reminders or synchronize external calendars. Refresh retrieves changes from other sessions; a failed refresh clears the loaded projection.
