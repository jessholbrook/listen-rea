# Q&A over researcher PDF observations

Create an analysis containing [explicitly included researcher PDF notes/corrections](pdf-observations.md). In **Analysis → Ask about researcher PDF observations**, enter a question and submit it. This panel is separate from participant-evidence Q&A. It does not require an observation synthesis or change participant theme coding/counts. Ordinary questions remain ephemeral; [Ask and save PDF answer draft](pdf-observation-answer-reviews.md) separately saves a private answer for explicit review/inclusion.

OpenAI receives the question, reporting language and only the current analysis's included notes, corrections, grounding judgments, PDF IDs and review versions. It does not receive PDF files, extracted pages, original asked questions/anchors, participant answers, reviewer identities, private revision history, response/turn IDs or source fingerprints through this request. Text written inside the included fields is sent as part of those fields. Neither appendix inclusion alone nor opening the panel makes a provider request.

Answers cite an exact PDF ID, included review version, field (`notes` or `correction`) and contiguous quote from that field. The citation validator is shared with observation synthesis. Invented/stale sources, invented quotes and cross-field substitutions are rejected. If a model answer has no citations, its text is replaced with a fixed insufficiency message in English, Spanish or French; unsupported uncited claims are not displayed. Matching quotes are a mechanical identity check, not proof that the interpretation is sound. Researchers should review the cited annotations before using an answer.

The prompt treats the question and annotations as untrusted data. It asks for tentative interpretations of researcher observations and forbids claims of document verification, participant experiences, identity/sensitive traits, prevalence or population effects. Generation uses structured non-stored requests (`store:false`), at most 2,000 output tokens and a 50-second request deadline. The endpoint applies the existing per-instance limiter at ten questions per workspace per minute, requires edit authority, and uses existing AI budgets. Its input is bounded to a 5–2,000-character question and at most 100 included observations/150,000 serialized characters. These are application bounds, not a provider-wide retention guarantee.

The request names the exact analysis ID/version and current revision/concept scope. Before generation and again in a transaction before returning, the server checks current study data/language, analysis identity/version, response eligibility and exact included-review fingerprints. Late results cannot restore or write an analysis: ordinary Q&A never persists an answer; the explicit save action commits a private draft only after the same source/version checks. Source changes, withdrawal, erasure or a newer analysis cause the request to fail rather than return stale evidence.

Ordinary answers remain only in the current browser view with the submitted question and model/time provenance; explicitly saved drafts appear in a separate persistent review panel. Source links lead signed-in researchers to the original response/PDF review. **Clear PDF observation answer** removes it. Navigation, reload, a changed analysis/version/language or refreshed stale state clears the panel; a late reply to an unmounted panel is ignored. This is not a push notification or remote erasure of text already delivered to another browser. Ordinary questions/answers are not stored in local storage or application documents. Explicitly saved drafts stay internal unless reviewed and included; participant payloads and external API/MCP projections do not gain them. Provider usage counts are still recorded. Ordinary questions leave existing analyses/reviews/report links unchanged. Saving a private draft advances the analysis version but preserves existing report review and links until explicit inclusion.

Validation covers exact field/review citations, shared synthesis-validator regressions, minimal provider payload, bounded/non-stored requests, provenance, localized insufficiency, malformed/unavailable providers, auth/workspace/scope/source/version gates, source withdrawal/erasure and unchanged report state on failure. Mobile browser fixtures exercise the panel separately from participant Q&A, note/correction source labels/links, clear/error/reload behavior and a delayed response after analysis navigation/version change. Hosted verification uses disposable synthetic annotations and private files, records real provider operations and removes temporary accounts/files afterward.

[Saved and reviewed PDF-observation Q&A report appendices](pdf-observation-answer-reviews.md) are implemented with explicit inclusion and source cleanup.
