# Saved and reviewed PDF-observation Q&A

In **Analysis → Ask about researcher PDF observations**, choose **Ask and save PDF answer draft** to generate an answer and save it as a private draft. The ordinary **Ask about PDF observations** action remains ephemeral. The save action makes a new AI request; it does not import a previously displayed answer or accept client-supplied AI provenance.

Saved answers appear under **Saved PDF observation answers** and survive reload. Each keeps the original question, AI answer/citations, model, prompt version and generation time. Exact snapshots of the cited included PDF reviews are saved with it. Review history records each answer/citation revision, authenticated editor and time. The original generated answer and question cannot be overwritten through review or general analysis/report edits.

Edit the interpretation or remove unsupported citations, check **I reviewed this answer against its cited researcher notes or corrections**, and optionally select **Include this reviewed PDF answer in report appendices**. Editing text/citations clears both choices in the form. Review and inclusion are separate; drafts and reviewed answers can stay internal. Uncited insufficiency answers may be saved privately but cannot enter reports. Each included answer requires at least one exact PDF/review/field quote matching both its frozen sources and the current analysis sources.

Only the latest reviewed and explicitly included revision enters memo text downloads, shared memo/report appendices and editable decks. Output identifies the question, reviewed interpretation, exact note/correction citations, reviewer/time, answer revision, model/prompt provenance and whether the researcher edited it. Original-answer records and revision history are omitted; shared wording can match the original when you review it without editing. Signed-in source links lead to the original PDF review. These remain interpretations of researcher annotations, not participant statements or independently verified document facts, and do not change sample/theme counts. English/Spanish/French appendix labels preserve original question/answer/quote wording.

Saving a private draft or reviewing/editing a private-only answer increments the analysis version for concurrency but preserves memo review, report editions and share links. Inclusion, editing an already included answer, withdrawal or deletion of an included answer clears report editions/snapshots and shares and requires memo review again. Regenerating an analysis creates a new analysis without migrating its saved answers. Source edits, withdrawal, exclusion or erasure continue to invalidate the analysis through the existing source lifecycle; reports verify both live PDF-review snapshots and the exact reviewed Q&A projection from their source analysis. Downloaded copies cannot be recalled.

The server alone creates saved drafts at the guarded generation commit. It rechecks analysis/data/language/source versions before saving. Review/delete requests require editing authority, exact analysis ID/version and saved-answer revision. Metadata supplied through general analysis/report edits is ignored; strict review requests cannot replace the original question, generation provenance or frozen source snapshots. Limits are 20 saved answers per analysis, 50 revisions per answer and 250,000 serialized characters for the saved-answer collection. Failed generation, validation or storage-limit checks leave previous saved state intact. No additional key, domain or provider setup is needed.

Saved QA stays inside the analysis document. Existing study/response/PDF cleanup removes affected analyses and reports; no separate receipt or orphan-answer store is introduced. Participant payloads and read-only API/MCP projections do not gain these answers. The provider still receives only the explicit question and included notes/corrections/grounding references, not saved answer history or PDF files. Review and report inclusion do not make new AI requests.

Validation covers default-private drafts, exact source/review/field snapshots, review/inclusion and no-citation gates, immutable original/history, optimistic edits, authorization, provider failure, limits, private-only report preservation, report/deck projections, forged metadata, private projection isolation and edit/withdraw/delete/source-erasure revocation. Mobile Chromium uses a marked generated-answer fixture with real review APIs for save/reload, review/inclusion, history, report/source navigation, withdrawal and deletion. Hosted verification uses a disposable synthetic workspace and a real generated saved answer, then removes the temporary account/files.
