# Researcher-triggered OCR for scanned PDF pages

In **Responses → participant transcript → PDF text and verified passages**, extract native text, select a physical page without extracted text, then authorize **Transcribe this page with AI**. The unchecked permission names OpenAI, the selected page image, transcription purpose and the researcher's authority to process it. This is a separate researcher action; upload sharing and participant follow-up permissions do not trigger OCR.

The server sends only a raster of that one prepared PDF page and a literal-transcription instruction. It does not send other pages, the original PDF, filename/metadata, answers, notes, passages or private identifiers. Page images use high-detail vision so small text remains legible; generation uses `store:false`, a 45-second deadline, 5,000 output-token limit and strict `{text}` validation with 12,000 characters maximum. Empty results are permitted for illegible content. Those limits do not guarantee accuracy or provider retention beyond the configured API setting.

OCR is available only to signed-in editors for a submitted, currently matching PDF source. Initial AI transcription never replaces native or previously accepted page text. [Manual corrections to accepted OCR](pdf-ocr-corrections.md) preserve earlier versions and invalidate derived evidence. Each physical page supports one saved draft; reloading/repeating a saved draft request reuses it. Generation is limited to 20 requests per workspace per process rate-limit window, not a durable spending budget. Concurrent requests can both reach the provider, but only one draft is retained. Broader documents, AI regeneration of accepted OCR, handwriting guarantees, automatic quality scoring and participant OCR follow-ups are outside this stage.

Rendering runs in a credential-stripped child process with only PATH/NODE_ENV, a 15-second deadline, 128 MB V8 old-space cap, 3 MiB PDF input, at most 20 pages, a selected raster's longest edge at most 1,600 pixels and 4 MiB PNG output. PDF.js limits source images to four million pixels and disables XFA, eval and worker fetch. These controls are not an OS sandbox or total native-memory guarantee. Only prepared PDFs are rendered; annotation/action layers are not executed. Application credentials remain in the provider-calling parent, never the renderer.

## Private draft and verification

The private draft retains original output, provider/model/prompt version, time, physical page and attributed permission receipt. Compare the original page, correct the text and check the separate verification checkbox. Editing text resets this checkbox. The server requires explicit attestation, exact source/text digest, draft identity and latest passage-history version; client-supplied provenance and unrecognized fields are rejected.

**Save verified OCR text** fills only the empty physical page, preserves the original draft and stores attributed corrected text and before/after digests. It changes the PDF text digest, appends a private verification event, resets passage inclusion and removes derived analyses, report editions, snapshots and share links. Existing passage/history text stays available internally. The UI warns about this before saving. Late source edits, erasure and conflicting writes are rejected when state is rechecked.

A saved AI draft is not in the extracted-page array and cannot be selected as evidence. After OCR verification, separately select exact page/character passages, attest to them and opt into report inclusion. Only those selected passages enter a new analysis/report; the whole OCR draft, permission and correction history do not. Included passages carry physical page citations and a **Researcher-verified OCR** label in internal evidence views, shared memo/report text and presentation exports, localized for English, Spanish and French. OCR does not create interview quotations or change participant/theme counts. Further AI synthesis requires its existing explicit researcher action.

OCR lives inside the existing private `participantPDFText` document, so PDF deletion, response retention/purge, related source-context erasure and workspace cleanup remove drafts, permission records, accepted text and verification history through the existing cleanup path. Participants, external API and MCP projections do not receive OCR records.
