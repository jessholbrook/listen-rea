# Operations reporting

Open **Research library → Action center → Follow-up workload** or **Follow-up activity history**, set the filters and choose **Generate report preview**. Review the scope, local date, time zone, row count and ten-row preview. Check the scope-review acknowledgement to download CSV or plain text. Controls and report labels are available in English, Spanish and French. All current workspace members, including readers, can generate reports over their existing workspace access.

Workload files include workspace totals and assignee rows for the selected collection, title search and assignee visibility (everyone, unfinished or overdue). All matching assignees are included across dashboard pages. Totals retain their original whole-scope meaning when row visibility narrows the assignee list. Counts reuse the original queue selector, exclude completed tasks from due windows and resolve relative dates from the server’s current date in the viewer’s browser time zone. They describe tasks, not personal capacity; overlapping categories are not additive.

Activity files include all matching retained events across history pages. Filters intersect collection, exact task, person involved, action, changed field and inclusive local calendar dates. Rows include UTC timestamps, current collection/task names and IDs, current actor names, task versions, before/after assignment/date/status, and the title-change flag. Old title text, research excerpts, source labels/URLs, emails, recordings, private review comments and provider output are excluded. Departed members are masked using the existing history projection. Retention metadata states the omitted count for the selected task/collection; a filtered report is not a permanent audit trail.

Reports support at most **1,000 rows and 2 MB**. Larger scopes are rejected with a request to narrow filters, never silently truncated. Workload’s totals row counts toward the limit. A preview displays only its first ten rows; the file contains all matching rows within the limit, including zero rows for an empty activity scope. Files include scope metadata, generation time in UTC, report date and time zone. CSV cells are quoted, multiline/quoted labels are escaped, and spreadsheet formula prefixes are neutralized. CSV includes a UTF-8 BOM for spreadsheet compatibility; plain text uses tab-separated columns with embedded whitespace flattened.

An open preview or request guards filter changes, screen/language navigation, refresh and task links. Closing the preview releases the controls. Each download rebuilds current data in a transaction, checks membership and compares the reviewed content and configuration with a fingerprint bound to the current member, workspace and role. Changes to included counts, events, names, filters or access require a new preview. Erased research cannot be recovered through an old preview. Errors clear the preview and acknowledgement and require explicit regeneration; downloads are not automatically retried.

The report routes are authenticated **POST library/operations-report/preview** and **POST library/operations-report/export**. Strict schemas allow only the report kind, explicit filters, language and valid time zone; export also requires current fingerprint, acknowledgement and CSV/text format. Clients cannot provide counts, rows, report dates, authority or research results. Both routes reuse current task/history validation. Export responses are attachments with `Cache-Control: no-store` and `nosniff`. Reports and fingerprints are not stored on the server, and no shared link or new approval state is created.

Downloaded files are independent copies: later source erasure blocks future stale downloads but cannot recall copies someone already downloaded or shared. No email/domain setup, external provider, migration or environment variable is required.

Validation covers strict schemas and permissions, current counts, all-page history, local dates, localization, reader downloads, current names/roles, fingerprint rejection, source erasure, CSV formatting, formula handling, stable original records and oversized-report rejection.
