# Optional DOCX-aware interview follow-ups

For an open question with DOCX uploads, enable **Allow optional AI DOCX follow-up (OpenAI)** in the guide and publish. Enabling requires at least one follow-up slot. The setting is frozen into each admitted session; editing the draft does not enable it for existing sessions. Removing DOCX uploads or changing question type clears the setting in the editor.

Participants see a separate unchecked AI permission checkbox before upload. Sharing the prepared DOCX text does not grant AI permission. The optional notice explains the context limit and that the answer and description are also sent. Permission is bound to that upload, with its version, localized notice, provider, language and grant time. A retry cannot change permission on the same upload ID. Remove and upload again to change a draft’s permission. English, Spanish and French controls, receipts and fallback notices are available. Uploading alone makes no AI request.

## Generation and provenance

Only an eligible open answer with remaining probe budget, an active session, the frozen feature flag and current, separately permitted DOCX draft can use prepared text. Declines, scripted questions and questions already derived from an image, PDF or DOCX skip document probing. DOCX takes priority over PDF and image probes when multiple separately permitted uploads accompany the answer. One document attempt is made; unavailable, rejected or unsupported document output advances the normal guide without another document provider call. Without DOCX AI permission, ordinary written-answer moderation may still run without receiving DOCX text.

The server reads the private prepared JSON snapshot, not original Word bytes. Only the first 20 prepared paragraphs, capped at 1,000 UTF-16 code units each without splitting a surrogate pair, are sent. Original paragraph numbers are preserved. The payload contains interview language, study goal, guide question/instructions, participant answer/description, bounded paragraphs and their exact candidate phrases. It excludes original files, omitted content, comments, hidden/deleted text, links as active targets, researcher notes, verification history and other responses. Provider generation uses `store:false`, a 50-second deadline, 600 completion tokens and an existing rate bound of 20 document attempts per interview.

The server derives up to three exact leading phrases of two to four words per supplied paragraph (a single-word paragraph can also qualify), with 3–60 character phrases and a maximum of 60 candidates. Unsafe or oversized candidates are skipped. The output schema restricts the quote to those supplied phrases; no usable candidate means no generation. The versioned prompt includes a literal-quote example. A usable result must be one question, no longer than 400 characters, containing the entire chosen phrase from its matching supplied paragraph. The paragraph/quote must match exactly. Malformed output, invented references, multiple questions, unsafe requests and unavailable storage/provider cannot create a document question. The model is instructed to treat all participant/document content as untrusted, avoid factual authentication or sensitive inference and return no question when insufficient. Programmatic checks establish reference identity and apply bounded rejection rules; they do not establish interview quality or factual accuracy.

The originating turn records status (`asked`, `none`, `rejected`, `unavailable`), model, prompt and permission versions, time, prepared-snapshot SHA-256, considered paragraph numbers and truncation status. Asked results retain the question, paragraph and quote. Rejected results retain a diagnostic reason code, such as a mismatched source or a missing literal quote, without retaining the rejected question. The current prompt and its later answer carry the source DOCX ID. Participants can view the authorized prepared text with the cited quote highlighted; references are to prepared paragraphs, not Word pages. Researchers see the provenance in the transcript. Original AI output is not automatically marked human-reviewed or copied into document-report evidence.

## Failure, deletion and boundaries

The written answer and file are saved even when a document question is unavailable. Exact answer-request retries do not generate or save a second turn. Source deletion waits for pending answer saves. It removes permission/source/probe metadata, redacts historical document-derived prompts and replaces an active question with a neutral localized text prompt. Active source erasure increments the interview version, rejects stale answers and rebinds independent image/PDF/DOCX drafts to the new version. Written answers and independent attachments survive; contextual attachment reviews, response translations, analyses, editions, snapshots and shares are cleared. File and whole-response retention/purge use the existing private-storage deletion lifecycle.

Researcher verified-passage Q&A/synthesis remain separate explicit actions over selected included evidence. They do not inherit participant interview permission or make document questions verified findings. External API/MCP response projections omit file permissions and probe provenance. Researcher grounding judgments, correction history and opt-in report appendices are implemented in the [DOCX review-to-report workflow](docx-review-workflow.md). Automatic quality scoring, broader document formats, Resend/domain setup and human interview-quality/pilot review remain deferred.
