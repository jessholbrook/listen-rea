# Richer interviewing and task measures

This bundle adds opt-in streaming voice, participant-requested screen-aware questions during a shared-screen task, a neutral return-to-task reminder, and source-linked task timers/outcomes. Human microphone, model-guidance and usability quality validation remain deferred.

## Streaming voice

For open questions without a screen-recording task, choose **Voice mode → Streaming voice · preview**. Grant separate permission for OpenAI to receive live microphone audio and return speech/transcription, then start. A WebRTC session streams audio and transcript events. Speaking interrupts generated question audio through server VAD and client response cancellation/audio-buffer clearing. Headphones and browser echo cancellation help avoid recording speaker output.

The spoken output is instructed to read the current frozen question. Automatic model replies are disabled. The displayed guide and existing answer endpoint remain authoritative: realtime output cannot advance the interview. Partial/final transcription updates a draft; stop streaming, review/edit it, then choose Continue. Final transcription replaces partial text, committed input-item order determines speech order, duplicate events are ignored, and generated interviewer speech never becomes a participant answer. Live audio is not stored by Echo Lab. The transcript becomes a saved research turn only through the existing answer submission. Refresh can lose an unsaved live draft; recorded voice retains its separate existing recovery workflow.

Stopping, switching voice mode, advancing, disconnecting or unmounting closes browser tracks/peer/audio resources. Connections that fail to open stop after a bounded wait. Browser sessions stop after ten minutes; production also schedules server hangup using the existing private Vercel queue. Delayed delivery can be retried; daily maintenance recovers expired call records. Local/manual-worker environments require browser closure or explicit maintenance for server cleanup. These are lifecycle controls, not a guarantee of exact provider billing or queue latency.

The server creates the call from a participant-authenticated, version-bound SDP offer and server-owned model/language/question settings. The application response contains only a scoped local ID, SDP answer and expiry; it omits the provider key and server hangup call ID. At most one unexpired reservation per interview and four per workspace are allowed transactionally. Exact retries reuse a current call; changed/expired requests cannot reopen it. The SDP answer is retained only with the temporary call record and cleared on close. A source change during negotiation triggers hangup instead of publishing a connection. Response erasure clears call records and queues any failed provider cleanup without retaining research text. Private recording-byte deletion proceeds even if hangup fails.

No new service or required environment variable is needed. The existing hosted AI key is used. `RESEARCH_REALTIME_MODEL` can optionally override the default `gpt-realtime`. A session-start usage event is recorded; realtime audio token cost is not currently reconciled to Echo Lab's usage ledger. Check provider billing for actual realtime costs. The speech question may be paraphrased despite instructions; no claim of exact audio fidelity or human comprehension is made.

## Screen-aware help and refocusing

During an existing consented screen capture, a second optional checkbox permits one current JPEG to be sent to OpenAI when **Ask about my current screen** is selected. No images are sent automatically. Each request uses the frozen task prompt and interview language. The browser limits the image size; the server verifies JPEG format/dimensions, strips metadata and bounds the provider call. Images remain transient, with no retained screen-image object. The underlying consented screen recording remains governed by its existing storage policy.

The model returns one neutral question, visible context and uncertainty. It is instructed not to solve the task, infer intentions, label someone off task, count clicks or declare success. Unclear/unrelated screens prompt clarification or a return to instructions. **Return to the task** provides a deterministic reminder without sending an image or calling a provider. This is participant-controlled recovery, not an automatic off-task detector.

At most three requests per capture, at least thirty seconds apart, are reserved before generation. Exact retries reuse a completed result and never spend another model call. Capture/turn status is rechecked after generation. Stopping capture, changing the task or erasing the response prevents a late result from appearing or recreating source data. Researcher views and reviewed guidance CSVs preserve model/prompt version, source/capture/question/revision IDs, image digest, original question/context/uncertainty and timestamps. They clearly label this material as optional AI guidance, never participant testimony or confirmed observations. Existing synthesis/Q&A does not ingest these prompts as evidence.

## Task timers and participant-reported outcomes

Screen-recording tasks offer a separate optional timer that also works without screen sharing or an AI key. Start, Pause, Resume and End are server-timestamped, versioned controls. Reload recovers the current attempt. Ending requires explicit review of **completed**, **not completed** or **skipped**, all reported by the participant. An open/paused attempt must end before the guide advances. Up to three attempts are allowed per task turn; request IDs deduplicate writes and competing/stale versions fail safely.

Active control time sums closed Start→Pause/End and Resume→Pause/End intervals. Wall control time spans the first Start receipt to End; paused time is the difference. Timestamps are clamped against the preceding event if a server clock moves backward. A hand-calculated reference of ten seconds active, five paused, then ten active yields 20 seconds active, 25 wall and five paused. Network latency affects event receipt times. These are measurements of the explicit timer, not verified time spent exclusively working in an external prototype.

**Visual Insights → Task timing and reported outcomes** shows each attempt with its original revision/question/source. Only ended attempts linked to a completed included native response/task turn enter completed measures. Other states remain visible and labeled separately. Missing timers do not become zero-duration observations. Repeated attempts and distinct people are counted separately; different revision/question scopes are not averaged together. Exact attribute/value filtering and fresh, reviewed CSV exports use current source/access fingerprints. Source inspection opens original participant turns. Responses with no exposed task turn do not enter the completed-task response count.

Source exclusion/erasure removes current eligibility and invalidates old exports; deleting or retaining out a response physically removes timers and guidance with it. Exported files cannot be recalled. Attempts store both interview version and original turn index so earlier draft edits do not misattribute a task to the wrong answer.

## Validation and limits

Focused checks cover hand-calculated timing, committed transcript ordering/duplicates, VAD configuration, consent/version/role boundaries, retry and source fences, reviewed exports, in-flight erasure, and independent private-byte cleanup during a provider outage. Browser checks use marked RTC/provider events plus real compiled-app persistence, actual synthetic screen capture, timer pause/reload/end, researcher source inspection/export and mobile layout. This verifies application behavior, not natural conversation quality or media connectivity on every participant network.

The development provider rejected realtime signaling with `invalid_api_key`. The existing hosted production key passed real Realtime signaling/hangup and real vision-guidance checks; release evidence is recorded separately. Human sessions remain necessary to assess microphone/speaker quality, interruption accuracy, task comprehension, guidance neutrality and real behavioral validity. Continuous automatic visual moderation, automatic off-task classification and independently verified external-site actions/success remain further work requiring study-specific instrumentation and validation.
