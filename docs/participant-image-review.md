# Researcher image review

In **Responses**, open a participant transcript and find the submitted attachment. **Researcher image review** saves a human image-quality judgment (usable, unclear/unreadable, irrelevant, privacy concern or uncertain) and review notes. When an image-based AI question was asked, reviewers also assess its grounding (supported, unsupported or uncertain) and can suggest corrected question wording.

An attachment starts **Not reviewed**. Saving an uncertain judgment is an explicit review, not an approval. The correction is an internal suggestion alongside the original evidence; it does not rewrite the participant transcript, regenerate a question, exclude a participant or verify authenticity. Explicitly included notes can appear in separate analysis/report appendices; see [inclusion and withdrawal](attachment-evidence.md). Automatic response scoring remains separate.

Each revision records all judgments, notes and suggested wording, the authenticated reviewer's ID/name and server timestamp. **Correction history** retains earlier revisions. Notes are limited to 2,000 characters, suggested wording to 1,000, and history to 200 revisions per image. All workspace edit roles (admin, researcher, collaborator) can review. Draft/unsubmitted attachments cannot be reviewed.

Concurrent editors cannot overwrite a newer review: saving uses the last revision and a server fingerprint of the exact source turn, image metadata/digest and AI question provenance. A conflicting save preserves unsaved form text and offers **Reload saved review**. Reload explicitly discards local edits. Changed source evidence rejects the old review rather than carrying it forward silently.

Reviews are stored separately from interview/turn data. Only signed-in researchers in the source study's workspace can access `GET`/`PUT /api/studies/:studyId/participant-images/:imageId/review`. Participant tokens, external read API/MCP credentials and anonymous access do not authorize that route. Internal reviews are not included in participant responses or model input. Responses use `Cache-Control: no-store`.

Deleting an image erases its entire review history in the same transaction as removal of attachment metadata. Whole-response deletion and retention cleanup also remove review records before private file cleanup. Existing image-provenance erasure/report invalidation rules still apply. Downloaded copies cannot be recalled.

Verification: API checks cover workspace/participant denial, attribution, correction preservation, concurrent writes, changed-source conflicts, validation, no-question constraints and image/response erasure. Generated-question fixtures are explicitly seeded and do not claim a live model generated them. The full suite passes 198 automated tests. Mobile Chromium checks cover judgments/history, persistence and conflict recovery. Hosted synthetic checks use disposable sources and verify private Blob revocation and removal of review history; existing owners and the paused pilot are preserved.
