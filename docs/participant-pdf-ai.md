# Optional PDF-aware interview follow-ups

In **Guide → open question**, enable PDF attachments and **Allow optional AI PDF follow-up (OpenAI)**, save and publish. The setting is off by default, requires at least one follow-up and is frozen with each admitted interview's guide. It does not change existing interviews. Researcher PDF synthesis remains a separate, explicit workflow.

Participants may answer without uploading, share a PDF without interview AI review, or check a separate AI permission for that upload. The permission names OpenAI and covers extracted PDF text, the participant's description and their current answer. The interface explains the 1,000-character-per-page context limit. Sharing alone never grants this permission. Each saved permission records provider, localized wording, language, version and time. Upload retries bind the exact file, description and permission choice; a lost acknowledgement cannot adopt a different permission. Controls are available in English, Spanish and French.

When an eligible open answer is submitted, the server validates the answer-bound draft before reading the stored prepared PDF. It extracts page text using the existing bounded child process, takes up to the first 1,000 UTF-16 characters of each physical page (at most 20,000 total), and sends only those page excerpts plus current question/goal/instructions, answer, description and interview language. PDF bytes, images, unselected page text, other responses and reviewer history are omitted. Encrypted/form PDFs are rejected at upload. Scanned/blank pages have no OCR and can be skipped. Context truncation and considered pages are recorded for researcher review.

Generation requests non-stored structured output (`store:false`), a 600-token output cap and a 50-second generation deadline started before file processing. Extraction independently has its existing 15-second process deadline; the storage read uses the existing adapter. A per-interview request cap bounds repeated use. These are request/resource bounds, not a provider-wide retention or document safety guarantee.

The model must propose one neutral question, a physical page and an exact contiguous short quote from that page excerpt. The server requires the same quote literally in the question and rejects wrong pages, invented anchors, multiple questions and obvious requests involving links, contact details or secrets. These checks establish text identity, not semantic support or factual accuracy. Embedded document/participant instructions are treated as untrusted data. The model must decline irrelevant, contradictory, instruction-only or insufficient excerpts rather than invent context.

PDF questions stay within the configured follow-up budget. A PDF-derived question does not recursively trigger another AI follow-up. When both image and PDF AI uploads are permitted for the same answer, PDF moderation takes priority, including a PDF attempt that is skipped or unavailable. Without PDF permission, the existing image/text path may still use the written answer under its own settings; it never receives the PDF through this path. Participant refusals skip probing.

For an asked question, participants see its page citation, quote and private PDF viewer. Researchers see asked/none/rejected/unavailable status, model, prompt/permission versions, generation time, prepared-file digest, considered pages and truncation. Generated prompts are model proposals, not independent document verification or response-quality/authenticity scores. Failed extraction, invalid output or an unavailable provider saves the submitted answer and PDF and proceeds without a PDF question. Exact answer retries do not generate a second question.

PDF-derived questions are stored with their source PDF IDs. Answer turns retain their original written responses. Those question/answer pairs may enter normal transcript analysis/export; any quoted PDF anchor remains question context, not a participant-answer citation or an extra respondent. Researcher evidence appendices still require separate verification and inclusion. No automatic theme/count changes or PDF fact-verification claims are added.

Erasing a source PDF removes its generated question metadata and redacts historical PDF-derived prompts while preserving written answers and independent attachments. An active PDF question is replaced with a neutral fallback; its version advances and independent later image/PDF drafts are rebound, so stale submissions cannot commit. Contextual image/PDF reviews and extraction tied to an erased prompt are reset. Analyses, response translations, reports, render-derived data and share links are invalidated through existing cleanup. Individual erasure waits for pending answer processing; whole-response erasure revokes source access and prevents a late result from committing. Previously transmitted or downloaded copies cannot be recalled.

Validation covers consent/settings/version gates before reads, immutable retries, bounds and minimal provider payload, exact page/quote validation, blank/scanned documents, provider failures/refusals, answer idempotency, current/historical question erasure and independent draft rebinding. Mobile Chromium checks English/Spanish/French permissions, lost upload acknowledgement/reload, actual cited-page pixels, follow-up answering and erasure. Hosted verification uses disposable synthetic documents; human research-quality/pilot review remains deferred.
