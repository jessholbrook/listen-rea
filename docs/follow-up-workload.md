# Follow-up workload dashboard

Open **Research library → Action center → Follow-up workload**, or choose **Follow-up workload** on Operations home. All current workspace members, including readers, can view it. English, Spanish and French controls work on mobile.

The dashboard shows workspace totals and a breakdown by current assignee, including a separate unassigned group and people with zero matching tasks. Counts cover unfinished, open, in-progress, completed, overdue, due today, the next seven calendar days and unfinished tasks without a due date. These categories overlap; they are not additive. Completed tasks are excluded from unfinished and due-window counts. The next-seven-day window includes today and excludes the seventh following day, matching the task queue exactly. Dates follow the viewer’s local calendar. Counts describe tasks, not people’s available capacity or performance.

Collection and task-title search intersect across totals and assignee rows. Row visibility can show everyone, people with unfinished tasks or people with overdue tasks; it does not alter workspace totals. Rows sort by overdue count, unfinished count, current name and ID. Twenty assignees appear per page, and changing scope, row visibility or local day returns to the first page. The selected collection and search remain when returning from the task queue. They are not saved across browser sessions.

Every count opens the original action-center queue with its exact collection, title search, assignee, status and due window. Opening reloads current data and resets queue pagination. Readers get the original read-only queue; editors use the existing task controls. Queue and history presets remain available in their original modes. Preset forms, task edits, triage changes and research drill-downs keep their original navigation guards.

The dashboard reuses the authenticated action-center response and queue selector. There is no new dashboard API, permission, storage record, task copy, export, provider or migration. Viewing it does not edit tasks or activity. The original source and assignee validation still runs when loading current tasks. Current member names are resolved on refresh; departed assignees are cleared by the existing task rules and their work becomes unassigned. An unexpected unavailable assignee stays an exact unnamed filter scope rather than being dropped or widened. Missing collection IDs remain selected; deleted or foreign research cannot be restored through dashboard links.

Use **Refresh action center** for changes from another session. A failed refresh removes stale counts and requires explicit refresh to recover. Local-date counts update at the next minute tick or window focus. No email, reminders or domain setup is required.
