# Cross-study research briefs

Research Library → **Research briefs** assembles reviewed, export-approved saved attachment answers into a private editable brief. This is one workflow: choose answers, order sections, write headings/summary/commentary, inspect exact sources, explicitly review the brief, approve its current revision, and download combined text or CSV. English, Spanish and French interfaces and export notices are supported. No additional AI call is needed to compose, edit, review or export a brief.

## Content and review

Create a draft from one to twenty distinct saved answers. Each section pins an answer ID and its latest approved review version. The brief stores references, researcher writing and content-free source dependencies; it does not copy answer text, citation quotes, private AI originals or earlier answer reviews. Current answer text and cited evidence are resolved by the server. Headings, summary and commentary are separately labeled researcher writing. Answer text/citations remain governed by the existing saved-answer review workflow.

After saving a draft, inspect the included answers and sources, check the review attestation, and separately approve the brief for export. Editing the form clears those checkboxes and disables downloads until saved. Adding answers or changing pinned revisions requires saving first so their server-resolved text can be inspected before approval. Section order, headings, commentary and researcher summary are editable; the interface language at save becomes the brief’s export-notice language. Source text is never translated automatically.

The brief has a monotonically increasing revision and the latest editor’s name/time. Updates and deletion require the current revision; competing edits fail with 409 instead of overwriting each other. Brief storage is latest-only, rather than an append-only history. Saved answer originals/history retain their existing independent rules. Creation uses a request ID and normalized input hash for retry-safe creation; reusing an ID with different content fails.

If a selected answer changes or loses review/export approval, the brief cannot export and its stale section text is hidden. Refresh the answer list, choose the latest approved revisions, save to inspect them, then review/approve again. A brief’s previous approval cannot bypass current answer approval. Withdraw brief export approval independently when needed. Downloaded copies cannot be recalled.

## Source lifecycle and privacy

Every list/detail/save/export resolves current authorized saved answers and their source dependencies. Files, review inclusion, verified passages, response eligibility/attributes and study source context retain the existing source-change checks. Source withdrawal/erasure or deletion of a dependent saved answer physically removes the complete brief, including summary/commentary. Request-driven retention uses the same path. Storage/provider errors are not treated as permanent withdrawal.

Erasure dependencies accumulate over the brief’s lifetime, including every generation input of every included answer, even uncited evidence and subsequently removed sections. Removing a section does not prove that its information was removed from free-text commentary. Source erasure or answer deletion therefore also removes briefs that previously used it. Dependencies remain content-free and private. This conservative rule prevents removed-section notes from bypassing source erasure. Create a new independent brief if a completely separate source set is needed.

All content is workspace-private. Editing roles can create/update/delete; read-only viewers can inspect and download currently approved briefs. Public/participant requests require researcher authentication and other workspaces cannot read or supply answer IDs. No public share link is created. Current-evidence buttons use the existing authenticated source resolver; full responses remain independently authorized.

## Exports and limits

Text (`.md`, served as plain text) combines the researcher title/summary, ordered section headings/commentary and the latest pinned approved answer exports with exact quotes, study/response/turn/file links, locator/source-review details, answer reviewer/version, model/prompt provenance and semantic retrieval provenance when present. CSV emits one row per current cited item with brief/section context and corresponding exact source/review/provenance fields. CSV formula cells are escaped. Private AI originals, older review text, participant attributes and uncited generation excerpts are omitted. A citation match does not establish interpretation quality, prevalence or comparable samples.

There are at most 50 briefs per workspace, 20 distinct answers per brief, 160 title/heading characters, 8,000 summary characters and 4,000 commentary characters per section. Stored documents, including accumulated dependency references, are bounded to 250,000 serialized characters. Combined exports are bounded to one million characters; narrow the brief if needed. Briefs now support both reviewed attachment answers and [reviewed transcript answers](library-transcript-answers.md).

## API

- `GET /api/library/briefs`: current private brief rows and editing capability.
- `POST /api/library/briefs`: `{requestId,title,summary,language,sections:[{answerId,answerVersion,heading,commentary}]}`. Always creates an unapproved draft; unknown fields are rejected.
- `GET /api/library/briefs/:id`: current derived preview, source state and export eligibility. Internal dependency/creation metadata are omitted.
- `PUT /api/library/briefs/:id`: full content plus current `version`, `reviewed` and `includeInExports`; every selected answer must be its current approved revision.
- `DELETE /api/library/briefs/:id`: strictly `{version}`.
- `GET /api/library/briefs/:id/export?format=md|csv`: independently revalidates sources, selected answer revisions, answer approval and brief approval inside the export transaction; private/no-store and nosniff headers.
