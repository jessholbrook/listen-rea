# Unified research planning

Open **Research library → Research planning**, or the **Research planning calendar** shortcut on Operations home. English, Spanish and French controls support mobile.

The calendar combines follow-up tasks with individual reviewer requests. Each review request occupies its own row and contributes its own count, so two reviewers on one packet can appear on different dates. Packets with no requested reviewers contribute no fictional deadline row; use the review inbox to assign reviewers. Unassigned filters match unassigned tasks. Departed or unavailable requested reviewers retain their exact coordinates and show an unavailable label; they cannot be scheduled from this view.

Use **Work queue** to choose all work, follow-up tasks or review requests. Collection, person, title search, month/day and completion filters intersect across counts and the paginated agenda. “Assigned to me” resolves for the current viewer. Task search matches task titles; review search matches packet and collection titles, using the original queue selectors. Completed tasks and approved current-content reviews are excluded by default and can be included explicitly. Overdue, next-seven-day and undated priorities always show unfinished work; their completion toggle is disabled. Month/day views support explicitly including finished work. A next-seven-day window includes today and excludes the seventh following date. Counts represent work items, not unique packets or unique collections.

Choose a date to narrow the agenda, choose it again or **Show whole month** to restore the month, and use month navigation/current month to plan across January 2000–December 2100. Grids start on Monday. Date-only labels and arithmetic preserve stored dates across leap years, year boundaries, time zones and daylight-saving changes. Today follows the viewer’s local date and updates on a minute tick or window focus. Refresh retrieves changes from other sessions.

**Open current item** reloads the exact original task ID/collection or packet generation in its existing editor. A missing target fails explicitly; a matching title or a replacement packet cannot be substituted. Readers can browse current queues and open current items without scheduling authority.

For task dates, choose **Reschedule task deadlines**. The existing reviewed triage flow supports up to 25 explicitly selected task/version coordinates across filters, dates and pages, with hidden-selection counts, before/after preview, acknowledgement and independent results. Date-only changes preserve assignment/title/progress/source links and retain original task-history attribution. Real task changes make dependent handoff approvals stale; no-op rows preserve versions/history. Review rows never become task targets.

For a reviewer request, choose **Schedule review deadline**. Set a valid date or choose **Clear review deadline**, then preview. Preview reads the exact current packet generation and requested reviewer through the existing planning endpoint and captures its current packet/review versions and content signature. It displays the current reviewer, decision and before/after date without writing. Applying requires a separate acknowledgement. The original feedback endpoint checks those coordinates again before changing the deadline. Concurrent edits, removed reviewers, source changes and replaced packets fail rather than update another request. Date-only review changes preserve existing reviewer decisions and final approval; they send no reminder. Existing no-op behavior preserves versions and activity history.

Pending task selections or a review scheduling form disable planning-language changes and refresh. Task selections can span filters until their preview locks them. Review scheduling locks the calendar filters immediately. Cancel/finish explicitly reloads both queues while retaining the chosen planning scope. A failed or interrupted write clears the apply controls and requires refresh/inspection; it may already have committed and is never automatically retried. A failed overview load clears both agendas and the grid together, with an explicit refresh to recover.

The read-only **GET library/unified-planning** route composes the existing authenticated action-center and review-inbox projections in one transaction, checks current workspace membership/edit access and commits existing stale-source cleanup. It rejects query parameters, extra path segments and mutations. Valid reads preserve task/review/history records. Source erasure removes linked rows from both kinds and invalidates old scheduling coordinates; the view stores no separate calendar records or copies of research. Scheduling uses the original task and review endpoints. No migration, provider call, new environment variable, email/domain setup or external calendar synchronization is introduced.

Follow-up calendar settings and deadline reports are available under **Action center → Follow-up calendar**. Combined planning settings and exports are available through [unified planning views and reports](unified-planning-views-reports.md).
