# Saved and reviewed Research Library answers

In **Research library → Attachment evidence**, choose **Ask & save draft** to generate and retain a cited answer. Ordinary **Ask** stays temporary. The save action sends the same bounded, explicitly included attachment-evidence payload as temporary Q&A, then stores the server-generated answer only after its sources pass revalidation. No client-supplied AI answer or provenance is accepted. No-citation, empty, failed or stale generations cannot create a draft.

Saved answers belong to the workspace. Open **Saved library answers** to inspect the immutable original, citations, source context and attributed review history. Edit answer text, keep a subset of the original exact citations, explicitly attest to review, and separately approve the new revision for export. Removing every citation, inventing/shortening a quote, citing another answer’s source, or approving an unreviewed revision is rejected. Editing answer text or citation selection clears the review/export checkboxes in the UI. API callers must make the same explicit review choices. Questions, language, original sources, model/prompt/time and previous revisions cannot be rewritten.

Source views retain study/revision/optional concept, response/turn/file IDs, evidence type, exact page/paragraph/slide offsets and OCR marker, or observation field/grounding, plus reviewer/version/time. **Open current evidence** rechecks inclusion and source identity; **Open response** opens the authorized original response and its existing private attachment viewers. Researcher observations/corrections stay distinct from document excerpts and participant statements.

## Review and exports

Each update appends an attributed revision with an optimistic version check. Concurrent or stale updates return HTTP 409. Inspect the original and every previous review in separate expandable sections. A later private/unreviewed revision blocks export even if an earlier revision was approved. Withdrawing approval appends a new revision and blocks future exports. Deleting a saved answer removes its original, source snapshot and complete review history.

Downloads support reviewed text (`.md`, served as plain text) and CSV. They contain only the latest explicitly reviewed and approved answer, its retained complete exact citations, source provenance and authenticated source links, reviewer/version/time, original model/prompt/generation time and an edit marker. They exclude earlier answer text, the original unedited AI answer, unused citations, participant attributes and separate participant-answer/question fields. Included question/answer/quote text can itself contain personal details; there is no content redaction. CSV uses the existing formula-escaping and quoting rules. Source links require workspace authorization; exports do not create public shares. Check interpretations before sharing a downloaded file.

Exports revalidate the original cited-source snapshot and every input dependency inside the same database transaction as reading the current approved revision. Unsaved editor changes disable download buttons. A source or answer change can therefore block a download after the button was displayed. Downloads already copied cannot be recalled.

## Source changes, withdrawal and erasure

Source verification/review changes, inclusion withdrawal and content replacement remove affected saved answers, including immutable originals and private review history. Response exclusion, changes to attributes/revision/source turns, attachment removal and whole-response erasure do the same. Study title changes remove answers citing that study because title context was frozen in the original. Adding unrelated evidence, completing a different response or changing unrelated study settings preserves an answer whose supplied context is unchanged.

Every evidence record supplied to the AI remains the erasure boundary, including uncited input and citations removed by later reviews. Only originally cited source text is frozen; uncited dependencies retain content-free source references and fingerprints. The original citation set stays protected because its quote can still exist in the immutable original/history. A change removes the entire saved answer rather than attempting to rewrite that history. Review edits target observation citations for the affected file; verification edits target passage citations; prepared content replacement affects both. Private unaccepted OCR drafts preserve unchanged verified evidence. Lifecycle removals are part of the underlying source-write transaction. Whole-response retention/purge explicitly removes cross-study answers referencing the response before deleting source documents and media.

List, open, repeat-save, review and export also check inclusion and context fingerprints for every input dependency, plus exact frozen cited sources. A stale/missing source removes the record before returning it; normal list reads omit removed records. Unexpected storage outages/corrupt snapshots block access/export without treating an operational failure as permanent withdrawal. Current-source failures clear the editor and reload its list. Filter/language/navigation changes and aborts cannot restore late editor/download replies. Once explicitly started, a save may still finish on the server after the browser navigates away; refresh saved answers to see committed drafts.

## Access and bounds

Workspace members, including read-only viewers, can read saved answers and download currently approved exports. Viewers cannot generate, edit, withdraw or delete answers. Other workspaces and participant tokens do not grant access. Originals/history remain internal workspace data and are not projected into the external API, MCP, public memos or study-specific reports. No external scopes or public links are added.

Up to 100 saved answers per workspace, 20 review revisions per answer and 250,000 serialized characters per answer are allowed. Existing library question/retrieval/provider/rate limits continue to apply. Explicit save requests require a UUID request ID; an identical completed retry reuses its original without another AI call, and reusing it with different input returns HTTP 409. The browser retains that ID for an in-view failed-request retry and resets it after success or changed inputs. Concurrent requests that begin before the first commits can still invoke the provider more than once, but the transaction stores one answer per request ID. Reloading the page does not retain the retry ID. Delete unwanted drafts rather than repeatedly generating replacements.

Records use the existing workspace `documents` table; no schema migration, domain, new provider or new environment variable is required. Provider payload, retention and private Turso/Blob configuration follow [attachment evidence](library-attachment-evidence.md). Email delivery and human pilot review remain deferred. Exact citation matching verifies source correspondence, not sound interpretation, complete keyword coverage or real-study quality.

## Internal API

| Route | Behavior |
| --- | --- |
| `POST /api/library/attachments/qa` | `saveDraft: true` plus a UUID `requestId` generates and saves a validated draft; omitted/false stays temporary. |
| `GET /api/library/attachments/answers` | Current workspace summaries and edit capability; stale records are pruned. |
| `GET /api/library/attachments/answers/:id` | Current original, frozen cited sources and complete private review history. |
| `PUT /api/library/attachments/answers/:id` | Append a revision using `version`, answer, exact citations, `reviewed` and `includeInExports`. |
| `DELETE /api/library/attachments/answers/:id` | Remove the whole record using its current `version`. |
| `GET /api/library/attachments/answers/:id/export?format=md` | Download the current approved revision after source checks; `format=csv` selects CSV. |
